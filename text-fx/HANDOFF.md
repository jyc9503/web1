# 회사 Claude 인수인계: 텍스트 연출 효과 (드롭 / 상승 / 그라데이션)

이 폴더는 게임 텍스트 연출 3종의 기획서 초안과 동작 시안이다. 다음 작업은 회사 내부 기획서(규격), 기획 데이터, 클라이언트·서버 코드를 보고 기획서를 다듬는 것이다.

## 파일

| 파일 | 내용 |
| --- | --- |
| `spec.md` | 기획서 본문. 이 파일이 기준이다 |
| `index.html` | 동작 시안(단일 HTML, 브라우저에서 바로 열린다). 프리셋 값은 이 파일의 `PRESETS` 와 `spec.md` 4절의 프리셋 정의표가 일치한다 |

## 이미 정해진 것

`spec.md` 6절 "미결정·확인 필요"와 본문의 "(확인 필요)" 외에는 모두 기획자가 결정한 내용이다. 내부 규격이나 코드와 충돌하면 임의로 고치지 말고, 어떻게 충돌하는지 정리해서 기획자에게 물어본다.

## 코드와 내부 문서를 보고 확인할 것

`spec.md` 6절의 표가 확인 목록이다. 우선순위는 아래 순서다.

1. **기존 태그 처리 코드**: `<$wave_s>` 같은 태그를 파싱하고 렌더링하는 곳을 찾아, 새 프리셋을 어디에 어떻게 붙일지 확인한다.
   - 없는 프리셋 이름과 닫히지 않은 태그를 기존 코드가 어떻게 처리하는지 보고, 2절 규칙 표의 "(확인 필요)" 두 줄을 기존 방식으로 고친다.
   - 기존 색상 변경 태그의 규칙을 확인한다. 그라데이션은 이 규칙을 그대로 따르기로 했다.
   - `wave` 등 기존 이동 효과가 걸린 글자의 위치 처리 방식을 보고, 분신이 닿았을 때 밀림을 더할지 무시할지 제안한다.
2. **말풍선 대사의 화면 구성**: 분신은 대사 영역 밖으로 나가도 그리기로 했다. 다른 UI와 겹칠 때 그리는 순서를 정한다. 대사의 페이드인·아웃 투명도를 분신에 곱할 수 있는 구조인지도 확인한다.
3. **동시 대사 수와 성능 상한**: 효과 대사는 한 화면에 여러 개 뜰 수 있다. 실제로 몇 개까지 뜨는지, 화면 전체의 분신 수 상한을 어디에 둘지 제안한다. 시안은 대사 하나당 분신 16개, 분신당 잔상 4개이고 실기기 성능은 측정하지 않았다.
4. **글자 분할 기준**: 이모지와 결합 문자를 사용자가 보는 한 글자 단위로 묶어 나누는 기능을 엔진과 폰트가 지원하는지 확인한다. 안 되면 대안을 제안한다.
5. **기획서 문서 자체**: 내부 기획서 양식과 용어에 맞게 다듬는다. 5절 구현 참고(플머용)는 실제 코드 구조에 맞춰 고친다.

## 작업 방식 (요청)

- 기획서를 고칠 때는 무엇을 왜 바꿨는지 목록으로 남긴다.
- 결정된 내용을 바꾸고 싶으면 바꾸지 말고 "제안"으로 따로 적는다.
- 모르는 것은 추측해서 채우지 말고 6절에 미결로 남긴다.
- 시안(`index.html`)의 프리셋 값을 바꾸면 `spec.md` 의 프리셋 정의표도 같이 바꾼다.

# 회사 검토용 인계 파일 (HANDOFF.md)

이 저장소는 한 방향 초안 공간이다. 인계 후 회사에서의 수정은 이 저장소로 돌아오지 않는다.
사용자는 결과 파일을 로컬에 저장해서 회사 PC로 옮긴다. 그래서 **HANDOFF.md 하나만 옮겨도 모든 맥락이 전달되어야 한다.**

이 저장소는 회사 데이터를 볼 수 없다. 회사 PC의 회사 계정 Claude가 `spec.md`와 `HANDOFF.md`를 읽고, 회사 데이터 기준으로 검토하고 기획을 수정한다. 그 Claude는 이 대화를 모른다. 파일만으로 상황을 이해할 수 있어야 한다.

## HANDOFF.md 구성

```markdown
# <기획명> 회사 검토 요청 (v0.x)

## 이 문서가 무엇인가
이 기획이 무엇이고 지금 어느 단계인지 3~5줄.
이 기획은 회사 외부에서 회사 데이터 없이 작성되었다.

## 게임 맥락
대상: 카오스제로 나이트메어. decisions.md의 "게임 맥락" 항목(사용자가 알려준 용어·구조·기존 규칙)을 그대로 옮긴다.

## 함께 옮긴 파일 (있다면)
- spec.html, proto/, mockups/ : 프로그램·아트팀에 보여주는 시안. 값 검토는 아래 본문(spec 전문) 기준으로 한다.

## 건드리면 안 되는 것 (확정)
- 규칙 ID와 한 줄 요약. 사용자가 확정한 것만.

## 검증해 주세요 (검증필요)
| ID | 가정한 내용 | 무엇과 비교할지 | 바꿔도 되는 범위 |
|---|---|---|---|
| R-03 | 파괴 시작 +10 | 기존 유사 시스템의 실패 페널티 | 단계 ±2 |

## 결정이 필요합니다 (미정)
- ID, 선택지, 이 기획자(작성자)가 기울어 있는 안

## 회사 Claude에게 요청하는 작업
1. 위 표의 각 항목을 회사 데이터와 비교해 일치/불일치/데이터 없음으로 판정한다.
2. 불일치하면 수정안과 근거를 제시한다.
3. spec.md를 수정하고 버전을 올린다. 상태 배지를 갱신한다.
4. 변경 내역을 CHANGES.md에 정리한다.

## 기획서 전문
(spec.md 내용을 여기에 그대로 붙인다. 이 파일만으로 기획을 이해하고 수정할 수 있어야 한다.)

## 결정 기록
(decisions.md 내용을 여기에 붙인다.)

## 규칙
- 확정 항목은 바꾸지 않는다. 충돌하면 수정하지 말고 CHANGES.md에 질문으로 남긴다.
- 회사 비공개 수치는 문서에 직접 쓰지 말고 "회사 데이터 기준 반영"처럼 쓰고, 필요한 값만 기획자에게 직접 전달한다.
```

## 작성 순서

1. `spec.md`에서 상태가 `검증필요`/`미정`/`확정`인 항목을 전부 수집한다.
2. 검증필요 항목마다 **무엇과 비교할지**와 **바꿔도 되는 범위**를 직접 정한다. 비교 대상을 모르면 "관련 수치 전반"이라고 쓰지 말고, 후보 데이터 종류를 구체적으로 적는다.
3. 위 구성대로 `HANDOFF.md`를 쓰고, 회사 Claude에게 붙여넣을 한 줄 지시문을 대화에 함께 준다.
4. 커밋·푸시하고 브리핑한다.

## 사용자가 로컬에 저장하는 방법 알려주기

인계 파일을 만든 뒤 브리핑에 다음을 포함한다.
- 저장해야 할 파일 목록(보통 HANDOFF.md 하나, 필요하면 spec.html)
- GitHub 웹에서 해당 파일을 열어 내용을 복사하거나 다운로드하는 경로
- 회사 Claude에게 붙여넣을 한 줄 지시문

사용자의 회사 PC가 GitHub에 접속되는지는 알 수 없다. 접속이 안 되면 사용자가 폰·개인 PC에서 파일을 저장해 옮긴다.

## 보안 주의

- 이 저장소에는 회사 데이터를 쓰지 않는다. 가정값만 쓰고 `검증필요`로 표시한다.
- 회사에서의 후속 작업은 이 저장소에 올라오지 않는다는 전제다. 사용자가 회사 수치를 이 저장소에 올리려 하면 한 번 짚어 준다.

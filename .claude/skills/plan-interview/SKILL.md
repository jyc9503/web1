# 기획 인터뷰 후 자율 진행

사용자는 폰으로 이동 중에 작업한다. 타이핑을 줄이고, 인터뷰는 짧게 끝내고, 이후는 알아서 진행한다.

## 1. 인터뷰

`AskUserQuestion`으로 객관식 위주로 묻는다. 한 번에 최대 4문항, 최대 2라운드. 사용자가 이미 말한 내용은 다시 묻지 않는다.

### 1라운드 (필수)
- **기획 종류**: 콘텐츠/이벤트, 연출 시스템, 연출 기능, 스테이지 재미 시스템
- **목적**: 이 기획으로 유저가 얻는 경험이나 달성할 지표 (선택지 + 직접 입력)
- **결과물**: 기획서 HTML, 화면 시안, 동작 프로토타입, 한 장 요약 중 필요한 것
- **참고할 기존 사례**: 있으면 한 줄로 (없음 선택 가능)

### 2라운드 (종류에 맞춰 선택)
- 콘텐츠/이벤트: 기간·반복 여부, 참여 조건, 보상 성격, 진행 흐름(단일/단계형/경쟁형)
- 연출 시스템·기능: 연출이 쓰이는 순간(전투, 보상 획득, 컷신 등), 길이, 스킵 여부, 아트팀이 알아야 할 것
- 스테이지 재미: 플레이어가 느껴야 할 감정, 난이도 곡선, 반복 플레이 유인

사용자가 "알아서 해줘"라고 하면 그 항목은 가정한다.

## 2. 가정 규칙

- 답이 없는 항목은 합리적으로 가정하고 `[검증필요]`로 표시한다.
- 수치(확률, 비용, 기간, 보상량)는 사용자가 말하지 않았다면 전부 `검증필요`다.
- 회사 실데이터를 아는 척하지 않는다.
- 선택이 갈리는 곳은 추천안 하나를 정해 진행하고, 대안은 `미정`으로 남긴다.

## 3. 자율 진행 순서

인터뷰가 끝나면 사용자 확인을 기다리지 않고 순서대로 만든다.

1. `plans/<슬러그>/` 폴더 생성, `decisions.md`에 인터뷰 결과 기록
2. `spec.md` 작성 (규칙 ID 부여, 상태 배지, 연출이면 타임라인 표 포함)
3. `plan-doc` 스킬로 `spec.html` 생성
4. 요청된 결과물 생성: `mockups/`(화면 시안), `proto/`(동작 프로토타입), `summary.html`(한 장 요약)
5. 커밋·푸시, Artifact 게시
6. 브리핑

## 4. 브리핑 (CLAUDE.md 형식)

```
[기획명] v0.1
만든 것: 2~3줄
링크: URL
가정한 것: 핵심 3~5개
결정 필요: 최대 3개, 선택지와 추천
다음: 한 줄
```

## 5. 폴리싱 피드백 받았을 때

1. 피드백을 모아서 항목으로 정리한다. 모호한 건 합리적으로 해석한다.
2. `spec.md`부터 수정하고, 출력물(html)을 다시 만든다.
3. 버전을 올린다(v0.1 → v0.2). 확정된 결정은 `decisions.md`에 날짜와 함께 추가한다.
4. 바뀐 점만 3줄 이내로 브리핑한다.

## 한 번 더 확인할 것
- 모든 값에 상태(`확정`/`검증필요`/`미정`)가 붙었는가
- 폰 폭에서 읽히는가
- 브리핑이 한 화면에 들어오는가

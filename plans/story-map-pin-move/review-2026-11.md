## 한눈에

- **최신**: 「2차 복잡성 검토」와 「3차 정리」가 아래쪽에 있다. 기능을 빼거나 줄였고, 과한 작성 기준을 정리했고, 연출 기획서 본문을 15,700자에서 5,600자로 줄였다.
- **관점**: 플레이어 경험 → 기획자 작업 효율 → 문서 읽기 쉬움 순으로 봤다. 새 기능은 넣지 않고 지금 범위 안에서 다듬었다.
- **결과**: 14곳을 고쳤다. 가장 큰 것은 **폰에서 글자가 너무 작아지는 문제**와 **기획자 여러 명이 같은 품질로 만드는 기준**이다.
- **문서**: 연출 기획서를 본문(10분)과 부록으로 나눴고, 리드·PD 회의용 한 장을 새로 만들었다.
- **결정**: 4건 모두 정했다(맨 아래 「결정 결과」). 여러 기획자 운영 규칙은 회사의 파일 잠금과 기존 규칙으로 해결되어 뺐다.

## 어떻게 검토했나

1. **플레이어로 보기**: 프로토를 폰 가로 크기로 놓고 장면 1 → 대사 → 장면 2 → 닫기를 따라가며 "누가 어디서 어디로"가 읽히는지 봤다.
2. **기획자로 보기**: 스토리 기획자 여러 명이 같은 배경과 장소를 나눠 쓰며 연출을 만든다고 놓고, 막히는 곳·서로 망가뜨리는 곳·품질이 갈리는 곳을 봤다.
3. **리드로 읽기**: 본문만 읽고 무엇을 만드는지 알 수 있는지, 담당자가 필요한 곳을 바로 찾는지 봤다.
4. **정합성 점검**: 규칙 ID, 설정 키 수치, 예시 데이터, 프로토, 인계 파일이 서로 같은지 스크립트로 확인했다.

## 2차 복잡성 검토 (2026-11-21)

1차 정리 뒤 기준을 먼저 세우고 다시 봤다. 1차에서 유지하기로 한 것도 기준에 걸리면 다시 다뤘고, 문서는 사람이 읽는다고 보고 따로 검사했다.

### 기획 요소 기준 (K)

목표는 "누가 어디서 어디로 갔는지 한 번에 읽힌다", 쓰는 곳은 메인 스토리에서 가끔이다.

| 기준 | 묻는 것 |
|---|---|
| K1 목표 기여 | "누가 어디서 어디로"를 더 잘 읽히게 하는가 |
| K2 결정 부담 | 기획자가 정할 것이 늘어나는가 |
| K3 상호작용 | 다른 기능(특히 이어가기)과 만나 특수 경우를 만드는가 |
| K4 대체 가능 | 이미 있는 기능으로 같은 결과를 낼 수 있는가 |
| K5 구현 비용 | 상태·분기·예외·설정 키가 늘거나, "시각 하나로 화면 계산"을 깨는가 |
| K6 문서 비용 | 새 개념이나 반복 설명이 늘어나는가 |

걸리는 기준이 4개 이상이면 빼고, 2~3개면 단순화하고, 0~1개면 유지한다.

| 요소 | 걸린 기준 | 결과 |
|---|---|---|
| 도착 후 사라짐 | 6개 | 뺐다. 사라지면 위치 정보가 지워진다. 핀을 빼야 하면 다음 이어가기 연출에서 뺀다 |
| 겹침 다시 정렬 애니메이션 (1차에서 유지) | 4개 | 뺐다. 나란히 놓기는 그대로, 묶음이 바뀌면 바로 새 자리 |
| 핀별 궤적 끄기 | 4개 | 뺐다. 연출 단위 앞 궤적 끄기는 남김 |
| 이징 선택 | 3개 | 뺐다. 항상 천천히 출발·도착 |
| 핀 색 직접 지정 | 3개 | 뺐다. 번호별 팔레트 |
| 설정 키 35개 | 4개 | 23개로. 400ms 페이드는 하나로, 계산 상수는 계산식 안으로 |
| 툴 핀 옵션 (1차에서 유지) | 2개 | 「고급」으로 접었다(K-09) |
| 배경 해상도 자유 | 4개 | 확정 규칙이라 그때는 두었고, 3차 정리에서 2048×1152 고정으로 정했다 |
| 출발할 때 등장, 시간 고정, 이름표, 장소 상속, 이어가기 | 0~2개 | 유지 |

### 문서 읽기 기준 (D)

| 기준 | 묻는 것 | 전 | 후 |
|---|---|---|---|
| D1 분량 | 본문을 한 번에 읽을 수 있는가 | 연출 본문 15,700자(약 30분) | 7,400자(약 12~15분) |
| D2 순서 | 기획 내용으로 시작하고 읽는 순서대로 놓였는가 | 첫 3,300자가 안내·용어, 규칙은 번호 순 | 개요 다음 바로 장면 컷, 규칙은 읽는 순서로 6묶음 |
| D3 반복 | 같은 사실을 한 번만 설명하는가 | 흐름을 5곳에서 설명 | 장면 컷 + 흐름도 한 곳, 전이표·스토리 테이블은 부록 J |
| D4 기호 밀도 | 배지·ID가 글을 가리는가 | 본문 배지 107개 | 확정 배지는 그리지 않음. 남은 배지 11개(검증필요) |
| D5 문장 | 한 칸이 한 번에 읽히는가 | 120자 넘는 칸: 연출 3, 툴 16 | 0, 0. 툴 저장 필드 이름은 부록 A에만 |
| D6 묶음 | 버전·이력이 흩어져 있는가 | 버전 4종, 이력 14행 | 묶음 버전 v0.18 하나, 이력은 최근 3개 |

본문 규칙은 54개 중 35개만 남기고, 저장 방식·단위·구현 세부 19개는 부록 J로 옮겼다. 툴 본문은 12,000자 → 10,800자다(단축키 표를 부록 D로).

### 3차 정리 (묶음 v0.22)

배경 해상도는 2048×1152로 고정했다. 속도 환산, 장소 붙는 반경 비례, 해상도 교체 시 좌표 변환(툴 M-07), 검수 Q-15, `width`·`height` 열, 설정 키 하나가 함께 없어졌다(설정 키 22개).

**기획자가 지켜야 하는 규칙 중 과한 것**을 따로 봤다. 기준은 세 가지다: 목표나 다른 규칙과 부딪치는가, 정상적인 연출에도 자주 걸리는가, 지키려면 다른 것을 희생해야 하는가.

| 규칙 | 무엇이 과했나 | 결과 |
|---|---|---|
| G-03 직전 대사에서 누가 어디로 가는지 말한다 | "글을 읽지 않아도 안다"는 목표와 부딪친다. 대사를 맵 기능이 정한다 | 삭제. 사용 안내의 팁으로만 |
| G-09 색이 겹치면 핀 번호를 바꾼다 | 핀 번호는 이어가기에서 같은 핀을 가리킨다. 바꾸면 이어가기가 깨진다 | 삭제. 이웃 번호끼리 구분되는 팔레트는 아트 요구로 |
| G-08 이름표 6자, 같은 이름표 금지 | 번역에서 글자 수는 의미가 없다. 같은 이름표 둘은 정상이다 | 삭제. 실제로 겹칠 때만 툴이 경고(CK-17) |
| M-05 장소 이름 최대 10자 | 위와 같다 | 글자 수 제한 삭제 |
| G-01 3~8초, 사이에 대사 | 짧은 이동을 잘못처럼 보이게 하고, 대사 작성을 강요한다 | "8초 이하, 길면 나눈다"로 |
| G-07 대사가 들어가면 이어가기로 나눈다 | 규칙이 아니라 당연한 결과다 | 삭제. 이어가기 설명 한 줄로 |

남은 작성 기준은 5개(G-01, G-02, G-04, G-05, G-06)이고 모두 툴이 경고만 한다. 저장을 막는 툴 검사(CK 오류)는 데이터가 깨지는 경우뿐이라 그대로 두었다.

**문서 분량**: 연출 본문 7,400자 → 5,600자(아트·사운드 표는 부록 L, 회의 안건은 부록 F로, 규칙 문장 다듬기). 툴 본문 10,800자 → 9,300자(편집 조작 세부는 부록 E, 검증·미결은 부록 F로).

## 4차 정리: 과한 경고·안내 (2026-11-21)

경고와 안내를 세 가지로 봤다. 정해진 동작에 붙은 경고인가? 매번 같은 말인가? 같은 경고가 두 곳에 있는가?

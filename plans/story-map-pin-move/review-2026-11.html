§1한눈에

  • 최신: 「2차 복잡성 검토」와 「3차 정리」가 아래쪽에 있다. 기능을 빼거나 줄였고, 과한 작성 기준을 정리했고, 연출 기획서 본문을 15,700자에서 5,600자로 줄였다.
  • 관점: 플레이어 경험 → 기획자 작업 효율 → 문서 읽기 쉬움 순으로 봤다. 새 기능은 넣지 않고 지금 범위 안에서 다듬었다.
  • 결과: 14곳을 고쳤다. 가장 큰 것은 폰에서 글자가 너무 작아지는 문제와 기획자 여러 명이 같은 품질로 만드는 기준이다.
  • 문서: 연출 기획서를 본문(10분)과 부록으로 나눴고, 리드·PD 회의용 한 장을 새로 만들었다.
  • 결정: 4건 모두 정했다(맨 아래 「결정 결과」). 여러 기획자 운영 규칙은 회사의 파일 잠금과 기존 규칙으로 해결되어 뺐다.

§2어떻게 검토했나

  1. 플레이어로 보기: 프로토를 폰 가로 크기로 놓고 장면 1 → 대사 → 장면 2 → 닫기를 따라가며 "누가 어디서 어디로"가 읽히는지 봤다.
  2. 기획자로 보기: 스토리 기획자 여러 명이 같은 배경과 장소를 나눠 쓰며 연출을 만든다고 놓고, 막히는 곳·서로 망가뜨리는 곳·품질이 갈리는 곳을 봤다.
  3. 리드로 읽기: 본문만 읽고 무엇을 만드는지 알 수 있는지, 담당자가 필요한 곳을 바로 찾는지 봤다.
  4. 정합성 점검: 규칙 ID, 설정 키 수치, 예시 데이터, 프로토, 인계 파일이 서로 같은지 스크립트로 확인했다.

§3바꾼 것: 플레이어 경험

무엇이 문제였나 무엇을 바꿨나 어디
1080 기준 크기를 폰 가로(높이 약 390)에 맞춰 줄이면 이름표가 약 9pt, 핀이 약 31pt가 된다. 이름표가 가장 먼저 안 읽힌다. 핀 지름 36, 이름표 12, 장소 글자 13 아래로는 줄이지 않는다. 프로토 「스토리 시연」에 「폰 가로 실제 크기」 보기를 넣었다. R-57, F-13, 설정 키 3개, Q-21
핀 여러 개가 한꺼번에 움직이면 눈이 못 따라간다. 동시에 움직이는 핀은 3개 이하를 권장하고, 넘으면 툴이 경고한다. G-02, 툴 CK-18
연출 중에는 대사창이 숨어서, 무슨 이동인지 글로 보충할 수 없다. 연출 직전 대사에서 누가 어디로 가는지 말하도록 작성 기준에 넣었다. G-03
연출이 끝나면 대사창이 지도 아래를 덮는다. 예시의 숲도 대사창 영역에 걸려 있었다. 도착 지점과 장소 마크는 화면 아래 22% 밖에 두고, 툴이 경고한다. 예시의 숲을 y 922 → 880으로 옮겼다(이동 시간은 그대로). G-04, 툴 CK-19, V-05
장소 이름이 많으면 도착지가 묻힌다. 보이는 장소 마크는 8개 이하를 권장하고, 넘으면 툴이 경고한다. G-05, 툴 CK-20
이어가기가 여러 단이면 흐린 궤적이 계속 쌓인다. 규칙(R-25)과 계산식(F-10)의 표현도 달랐다. 바로 앞 연출의 궤적만 흐리게 남긴다(결정 반영). R-56, 설정 키 1개

§4바꾼 것: 기획자 작업 효율

무엇이 문제였나 무엇을 바꿨나 어디
기획자마다 길이·속도·장소 수가 제각각이면 같은 게임 안에서 연출 품질이 갈린다. 「연출 작성 기준」 9개를 기획서 본문에 두고, 툴 사용 안내에 「좋은 연출 기준」으로 옮겼다. 기계로 볼 수 있는 5개는 툴이 경고한다. G-01~G-09, 사용 안내
장소는 같은 배경의 모든 연출이 함께 쓴다. 한 사람이 옮기면 다른 사람 연출이 모르게 바뀐다. 장소를 옮기거나 이름을 바꾸거나 지울 때 영향받는 연출 목록을 보여주고 확인을 받는다. 툴 M-08, M-09 → 결정 후 뺌
새 id를 "가장 큰 id + 1"로 주면 두 사람이 동시에 만들 때 겹친다. 기획자마다 id 대역을 나눠 쓴다. 회사 채번 규칙이 있으면 그것을 따른다. 툴 D-05 → 회사 채번 규칙
묶음 이름 규칙이 없어 목록이 사람마다 다르게 쌓인다. C03_MOVE처럼 C<챕터>_<내용>, 이벤트는 EV<번호>_<내용>. 툴 S-07 → 결정 후 뺌

§5바꾼 것: 문서 읽기 쉬움

무엇이 문제였나 무엇을 바꿨나
기획서가 820줄이라 리드가 어디까지 읽어야 하는지 알 수 없었다. 본문(무엇을 만드는지)과 부록 A~I(데이터, 설정 키, 계산식, 예시, 예외, 회사 데이터 연결, 구현, 검수, 작업 목록)로 나눴다. 「누가 어디를 읽나」 표를 다시 썼다. 규칙 ID는 하나도 바꾸지 않았다.
글로만 설명해서 화면이 머리에 안 그려졌다. 본문 앞쪽에 「플레이어가 보는 장면」을 두고 게임 화면 컷 4장과 유저가 읽는 순서를 넣었다.
「연출」「연출 맵」「장면」이 섞여 있었다. 한 건은 「연출」, 「장면 1」은 예시 이름으로만 쓴다.
툴 기획서도 표가 길었다. 속성 패널 저장 위치, 검사 항목, 작업 목록을 부록으로 옮겼다.
리드·PD에게 보여줄 자료가 없었다. 회의용 한 장을 새로 만들었다: 왜 필요한가, 유저가 보는 장면, 범위, 만드는 쪽 규모, 위험, 회의에서 정할 것.

§6일부러 안 바꾼 것

항목 이유
연출 템포(등장 800ms, 마무리 1000ms, 탭 완료 300ms) 메인 스토리에서 가끔 나오는 연출이라, 한 번 볼 때 여유 있게 읽히는 지금 템포가 맞다. 실제 기기에서 설정 키로 조정한다.
지도 전체를 보이게 하는 방식(R-19) 확정된 규칙이다. 넓은 폰의 좌우 여백은 다음 버전 후보로 남겼다.
도착 표시 없음 확정된 방향이다. 도착은 장소 마크와 멈춘 핀으로 읽는다.
카메라 연출 기능 완성 후 재검토로 이미 정했다(R-16).

기획 요소 기준 (K)

목표는 "누가 어디서 어디로 갔는지 한 번에 읽힌다", 쓰는 곳은 메인 스토리에서 가끔이다.

기준 묻는 것
K1 목표 기여 "누가 어디서 어디로"를 더 잘 읽히게 하는가
K2 결정 부담 기획자가 정할 것이 늘어나는가
K3 상호작용 다른 기능(특히 이어가기)과 만나 특수 경우를 만드는가
K4 대체 가능 이미 있는 기능으로 같은 결과를 낼 수 있는가
K5 구현 비용 상태·분기·예외·설정 키가 늘거나, "시각 하나로 화면 계산"을 깨는가
K6 문서 비용 새 개념이나 반복 설명이 늘어나는가

걸리는 기준이 4개 이상이면 빼고, 2~3개면 단순화하고, 0~1개면 유지한다.

3차 정리 (묶음 v0.19)

배경 해상도는 2048×1152로 고정했다. 속도 환산, 장소 붙는 반경 비례, 해상도 교체 시 좌표 변환(툴 M-07), 검수 Q-15, width·height 열, 설정 키 하나가 함께 없어졌다(설정 키 22개).

기획자가 지켜야 하는 규칙 중 과한 것을 따로 봤다. 기준은 세 가지다: 목표나 다른 규칙과 부딪치는가, 정상적인 연출에도 자주 걸리는가, 지키려면 다른 것을 희생해야 하는가.

규칙 무엇이 과했나 결과
G-03 직전 대사에서 누가 어디로 가는지 말한다 "글을 읽지 않아도 안다"는 목표와 부딪친다. 대사를 맵 기능이 정한다 삭제. 사용 안내의 팁으로만
G-09 색이 겹치면 핀 번호를 바꾼다 핀 번호는 이어가기에서 같은 핀을 가리킨다. 바꾸면 이어가기가 깨진다 삭제. 이웃 번호끼리 구분되는 팔레트는 아트 요구로
G-08 이름표 6자, 같은 이름표 금지 번역에서 글자 수는 의미가 없다. 같은 이름표 둘은 정상이다 삭제. 실제로 겹칠 때만 툴이 경고(CK-17)
M-05 장소 이름 최대 10자 위와 같다 글자 수 제한 삭제
G-01 3~8초, 사이에 대사 짧은 이동을 잘못처럼 보이게 하고, 대사 작성을 강요한다 "8초 이하, 길면 나눈다"로
G-07 대사가 들어가면 이어가기로 나눈다 규칙이 아니라 당연한 결과다 삭제. 이어가기 설명 한 줄로

남은 작성 기준은 5개(G-01, G-02, G-04, G-05, G-06)이고 모두 툴이 경고만 한다. 저장을 막는 툴 검사(CK 오류)는 데이터가 깨지는 경우뿐이라 그대로 두었다.

문서 분량: 연출 본문 7,400자 → 5,600자(아트·사운드 표는 부록 L, 회의 안건은 부록 F로, 규칙 문장 다듬기). 툴 본문 10,800자 → 9,300자(편집 조작 세부는 부록 E, 검증·미결은 부록 F로).

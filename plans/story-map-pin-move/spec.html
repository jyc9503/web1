§1개요

스토리 대사 사이에 배경 지도 한 장을 깔고, 장소 이름과 핀(캐릭터나 함대 같은 대상)을 올려 정해진 경로로 움직인다. 유저는 글을 읽지 않아도 누가 어디서 어디로 갔는지 알 수 있다.

  • 목표: "누가 어디서 어디로 갔는지 한 번에 읽힌다."
  • 쓰는 곳: 메인 스토리에서 이동이 중요한 장면에 가끔 쓴다. 한 번에 8초 안쪽으로 짧게 끝난다.
  • 만드는 법: 스토리 기획자가 편집 툴에서 배경을 고르고, 장소 이름을 새기고, 핀마다 Actor와 경로를 정한다. 스토리 테이블의 행에서 연출 id로 맵을 열고 닫는다.
  • 이번 범위가 아닌 것: 카메라 이동, 유저가 핀을 조작하는 기능, 전투·탐험 화면의 지도.
  • 읽는 법: 본문은 무엇을 만드는지, 부록은 어떻게 만드는지(데이터, 수치, 계산식, 예외, 검수, 구현 규칙)다. 배지가 없는 항목은 확정이고, 검증필요·미정만 배지로 표시한다. 테이블·키 이름과 수치는 자리표시다. 용어와 담당별 읽을 곳은 부록 K, 아트·사운드 요청은 부록 L, 프로그램실 회의 안건은 부록 F 끝에 있다.

§2플레이어가 보는 장면

메인 스토리에서 이동이 중요한 순간에 가끔 나온다. 유저는 직전 대사로 "누가 어디로 가는지" 듣고, 지도에서 그 이동을 눈으로 확인한 뒤 다음 대사로 돌아온다. 아래는 예시 연출 두 개(장면 1, 장면 2)를 게임 화면 그대로 그린 것이다. 배경과 인물은 자리표시다.

유저가 읽는 순서:

  1. 직전 대사: 누가 어디로 갈지 듣는다.
  2. 장소 이름: 지도가 나타나면 장소 이름이 먼저 읽힌다. 이야기에 나오는 장소만 보인다.
  3. 출발: 핀이 움직이기 시작하고 효과음이 한 번 난다. 핀이 여럿이면 시차를 두고 출발한다.
  4. 궤적: 지나온 길만 점선으로 남아, 끝난 뒤에도 "어디서 왔는지"가 보인다.
  5. 도착과 대사: 대사창이 돌아와도 도착 지점은 가려지지 않는다. 지도는 닫힐 때까지 대사 뒤에 남는다.

화면 탭 한 번으로 언제든 끝 상태로 넘길 수 있다.

시간으로 보면, 배경과 핀이 400ms씩 나타난 뒤 0ms에 이동을 시작하고, 마지막 도착 1000ms 뒤에 끝난다. 열린 맵에서 이어지는 연출은 나타나는 단계 없이 바로 시작한다. 전체 상태 전이표는 부록 J에 있다.

§6부록 A. 데이터 설계

설계 원칙

  • 엑셀과 JSON을 나눈다: 사람이 손으로 고치거나 다른 테이블과 이어지는 것(배경, 장소, 연출 머리, 속도 프리셋, 설정)은 엑셀 테이블에 둔다. 툴이 만드는 것(핀, 경로 점, 장소 보임)은 연출 1건당 JSON 1개에 둔다.
  • 회사 테이블 규칙: 행마다 id, 다른 테이블 참조는 link_*_id, 열 이름은 소문자 + 밑줄, 그룹 id는 쓰지 않는다.
  • 사람이 읽는 값: 좌표는 배경 픽셀 정수, 시간은 ms 정수, 글자는 문자열 키, 선택지는 영문 대문자 열거값.
  • 비워 두면 기본값: 엑셀은 칸을 비우고, JSON은 필드를 생략하면 기본값을 쓴다.
  • 복사본 없음: 같은 값을 두 곳에 두지 않는다. 장소 좌표는 장소 테이블에만, 이어가기 시작 위치는 앞 연출에만 있다.

왜 이렇게 나눴나

판단 이유
핀·웨이포인트를 JSON으로 회사 테이블은 그룹 id를 쓰지 않고 행마다 id가 필요하다. 점 하나마다 id를 붙여 엑셀에 늘어놓으면 손으로 관리할 수 없다. 툴이 통째로 쓰고 읽는 데이터라 JSON이 맞다
배경·장소는 엑셀로 장소 이름은 문자열 키로 번역되고, 여러 연출이 같은 장소 id를 가리킨다. 사람이 표로 보고 고칠 일이 있다
연출 머리(map_scene)를 엑셀에 스토리 행이 link_map_scene_id로 가리킬 id가 테이블에 있어야 한다. 배경과 앞 연출도 다른 행을 가리키는 연결이라 link_*_id로 둔다
장소 보임을 연출 JSON에 연출마다 달라지는 값이고 툴에서 체크로 고른다. 이어가기는 바뀐 것만 적어서 중복이 없다
핀은 번호(pin_no)로 식별 이어가기 연결 안에서 같은 핀을 번호로 이어 붙인다. 같은 Actor 핀이 둘이어도 헷갈리지 않는다
웨이포인트는 순서 번호 없이 목록 순서로 점을 끼워 넣어도 번호를 다시 매길 필요가 없다
속도를 프리셋으로 "걷기가 느리다"는 피드백을 프리셋 값 하나로 모든 연출에 반영한다. 특별한 장면만 duration_ms로 고정한다
필드 하나에 뜻 하나 start_offset_ms는 항상 "기준점에서 몇 ms 뒤"다. 기준점이 무엇인지는 start_type이 정한다
JSON 안의 id 참조 actor_id, place_id, speed_preset_id는 엑셀 검사가 닿지 않는다. 툴 저장 전 검사와 빌드 검사로 막는다(「부록 G 구현 전달사항」)

§8부록 C. 계산 규칙

게임과 툴 미리보기가 같은 화면을 내려면 같은 식을 써야 한다. 프로토타입이 이 식 그대로 동작한다. 식 자체는 제안이고, 엔진에 같은 결과를 내는 기능이 있으면 그것을 써도 된다.

ID 항목 식 상태
F-01 화면 배치 화면 안에 16:9 영역을 가운데에 가장 크게 잡는다(전체가 보이게). 화면 좌표 = 영역 원점 + 배경 px × (영역 폭 ÷ 2048). 검증필요
F-02 곡선 (SMOOTH) 점 i에서 i+1까지를 3차 베지어로 잇는다. 제어점은 P[i] + out[i], P[i+1] + in[i+1]. 핸들이 없는 점은 out[i] = (P[i+1] − P[i−1]) ÷ 6, in[i] = −out[i]를 쓴다. 양 끝 점은 없는 이웃 대신 자기 자신을 쓴다. (Catmull-Rom과 같은 모양) 검증필요
F-03 직선 (LINE) 점과 점을 직선으로 잇는다. 핸들은 무시한다.
F-04 경로 길이 곡선은 구간마다 16등분한 점을 직선으로 이은 길이의 합. 단위는 배경 px. 검증필요
F-05 이동 시간 이동 시간 = 길이 ÷ 프리셋 speed_px × 1000을 100ms 단위로 반올림하고, 최소 100ms. duration_ms가 있으면 그 값을 쓴다. 점이 하나뿐이거나 길이가 0이면 이동 없음. 검증필요
F-06 출발 시각 TIME: 오프셋. AFTER_ARRIVE: 기준 핀 도착 시각(출발 + 이동 시간) + 오프셋. 기준 핀이 이동 없는 핀이면 도착 시각 = 출발 시각.
F-07 진행 u = (지금 − 출발) ÷ 이동 시간을 0~1로 자른다. 천천히 출발·도착: u < 0.5면 2u², 아니면 1 − (2 − 2u)² ÷ 2. 핀 위치는 경로 길이의 그 비율 지점(거리 기준). 검증필요
F-08 연출 길이 등장 = 열린 맵에서 이어지면 0, 아니면 MAP_FADE_MS × 2(배경 다음 핀). 이동 끝 = 가장 늦은 도착 시각. 종료 = 이동 끝 + 마무리 대기(연출의 outro_ms, 없으면 MAP_OUTRO_MS).
F-09 겹침 벌리기 쉬는 핀끼리 화면 거리가 핀 지름 × 0.9보다 가까우면 한 무리다. 무리의 중심은 평균 위치. 간격은 핀 지름 × 1.15와 (무리에서 가장 긴 이름표 폭 + 6px) 중 큰 값. 원래 x가 작은 핀부터, 같으면 핀 번호 순으로 왼쪽에서 오른쪽으로 놓는다. k번째 핀의 x = 중심 + (k − (n − 1) ÷ 2) × 간격. 묶음이 바뀌면 그 프레임에 바로 새 자리를 쓴다(보간 없음). 검증필요
F-10 이어가기 시작 상태 맨 앞 연출부터 차례로 따라가며 계산한다. ① 핀 위치: 핀 번호마다 가장 마지막에 나온 연출의 끝 위치(목록에서 빠진 핀은 없음). ② 장소 마크: 연출마다 보임 목록을 더하고 숨김 목록을 뺀 결과. ③ 앞 궤적: 바로 앞 연출의 경로(R-56).
F-11 탭 완료 탭한 순간의 연출 시각을 t0라 하면, 표시 시각 = t0 + (종료 − t0) × (탭 뒤 지난 시간 ÷ MAP_TAP_FINISH_MS).
F-12 방향 표시 이동 중인 핀의 삼각형은 지금 구간의 진행 방향을 가리킨다. 쉬는 핀에는 삼각형이 없다.
F-13 표시 크기 화면에 그리는 크기 = max(최솟값, UI px 값 × 화면 높이 ÷ MAP_UI_BASE_HEIGHT). 핀 지름·이름표 글자·장소 글자에만 최솟값이 있다(R-57). 검증필요

§12부록 G. 구현 전달사항

프로그래머에게 전하는 제안이다. 더 나은 방법이 있으면 바꿔도 되고, 화면 결과만 「부록 C 계산 규칙」과 같으면 된다.

  • 시각 하나로 화면을 계산한다: "연출 데이터 + 연출 시각 t → 배경 불투명도, 장소별 불투명도, 핀별 위치·불투명도·방향, 궤적 길이"를 돌려주는 함수 하나로 만든다. 탭 완료(R-53), 배속(R-54), 툴의 시간 이동, 로그 다시 재생(R-45), 세이브 복원이 모두 t만 바꾸면 해결된다. 겹침 정렬도 t 하나로 계산하므로 프레임 사이 상태가 없다.
  • 미리 계산: 연출을 불러올 때 경로 샘플 점, 구간 길이, 핀별 출발·도착 시각을 한 번 계산해 둔다. 이어가기는 앞 연출을 따라가 시작 상태를 계산한다(F-10).
  • 설정 값은 코드에 적지 않는다: 모든 수치는 설정 키에서 읽는다. 값을 바꾸고 다시 빌드하지 않고 확인할 수 있으면 좋다.
  • 폰 최소 크기: 핀·이름표·장소 글자는 F-13의 최솟값 아래로 줄이지 않는다. 폰 가로 화면에서 가장 먼저 깨지는 곳이다.
  • 궤적은 코드로 그린다: 리소스 없이 핀 색의 둥근 점선을 그린다. 두께와 간격은 UI px 설정 값이다.
  • 미리 불러오기: 스토리에 들어갈 때 그 스토리 행들이 가리키는 연출의 배경과 핀 아이콘을 미리 불러온다. 재생 순간에 멈칫하지 않게 한다. 검증필요
  • 데이터 검사: 연출 JSON 안의 actor_id, place_id, speed_preset_id는 엑셀 검사가 닿지 않는다. 툴의 저장 전 검사(툴 기획서 T-07)와 같은 규칙으로 빌드 때 한 번 더 검사하는 스크립트를 둔다. 손으로 고친 JSON도 걸러진다.
  • JSON 형식 버전: version이 아는 값이 아니면 연출을 건너뛰고 로그를 남긴다. 형식을 바꿀 때 버전을 올린다.
  • 세이브: 스토리 중간 저장이 있다면 "지금 열린 연출 id" 하나만 저장한다. 복원할 때 그 연출의 최종 상태를 계산해 바로 유지 상태로 띄운다.
  • 확인용 기능: 연출 id를 넣으면 스토리 없이 바로 재생하는 개발용 명령이 있으면 기획·QA 확인이 빨라진다.
  • 로그: 「부록 E 예외 처리」의 모든 줄은 연출 id와 핀 번호를 담은 로그를 남긴다.

이어가기 세부

연속된 이동을 여러 연출로 나눠 대사 사이에 끼워 넣기 위한 기능이다. 예를 들어 "A가 관측소로 간다 → 대사 → A가 탑으로 간다"를 두 연출로 만든다.

  • 이어가기 연출은 앞 연출 id만 가진다. 다음 값은 저장하지 않고 앞 연출 데이터를 따라가며 계산한다(계산 순서는 부록 C의 F-10).
  • 시작 위치: 앞 연출과 같은 번호의 핀은 앞 연출에서 그 핀이 끝난 위치
  • 앞 궤적: 바로 앞 연출의 경로(R-56)
  • 장소 마크: 앞 연출 끝에 보이던 마크는 계속 보인다. 이 연출의 장소 목록에는 새로 보일 마크와 숨길 마크만 적는다.
  • 앞 연출을 고치면 뒤 연출의 시작 위치도 자동으로 따라간다. 툴은 영향받는 뒤 연출 수를 알려준다.
  • 다른 연출이 참조 중인 연출은 툴에서 지울 수 없다.
  • 앞 연출에 없던 핀을 추가하면 그 핀만 일반 등장(400ms 페이드인)한다.
  • 앞 연출에 있던 핀을 이 연출의 핀 목록에서 빼면 그 핀은 연출이 시작될 때 사라진다(R-49).
  • 연출 중에는 대사가 나오지 않으므로, 이동 사이에 대사가 들어가면 연출을 나눠 이어가기로 잇는다. 대사 없이 이어지는 이동은 한 연출 안에서 출발 조건으로 잇는다.

스토리 테이블 연동

회사 스토리 테이블은 한 행에 id가 있고 옆으로 열이 늘어선 형태이며, 내보내면 한 행이 {} 객체가 된다. 여기에 열 2개를 더한다. 열 이름은 자리표시다.

map_close bool (비움 가능) TRUE면 이 행을 시작할 때 열린 맵을 닫는다 검증필요
  • 한 행의 처리 순서는 맵 닫기 → 맵 열기 → 그 행의 대사다. 대사가 없는 행이면 연출만 재생하고 다음 행으로 넘어간다.
  • 편집 툴은 별도 툴이라 스토리 순서를 모른다. 게임은 "지금 열린 맵"만 보고 이어가기 여부를 판단하므로 순서 정보가 필요 없다.
  • 행에 기존 배경 열 값이 있어 배경이 바뀌면 맵은 자동으로 닫힌다.

§16부록 K. 읽는 법과 용어

  • 이 문서는 회사 밖에서 회사 데이터 없이 썼다. 테이블·열·필드·키 이름과 id 숫자, 설정 키 수치는 모두 자리표시이며 회사 확인 대상이다(부록 F).

  • 툴 상세는 별도 기획서 「맵 이동 연출 편집 툴」(plans/map-move-tool/)에 있다.

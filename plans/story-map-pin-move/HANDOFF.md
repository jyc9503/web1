# 스토리 맵 핀 이동 연출 + 편집 툴 회사 검토 요청 (연출 v0.19 / 툴 v0.19)

## 이 문서가 무엇인가

스토리 대사 사이에 배경 지도 위에서 핀(캐릭터·대상)이 경로를 따라 움직여 "누가 어디서 어디로 갔는지"를 보여주는 연출 기능과, 그 데이터를 만드는 편집 툴의 기획서다. 규칙·데이터 설계·프로토타입까지 끝났고, 회사 데이터에 맞추는 단계만 남았다.

- **이 기획은 회사 외부에서 회사 데이터 없이 작성되었다.** 테이블·열·필드·키 이름과 id 숫자는 모두 자리표시다.
- 이 파일 하나에 두 기획서 전문과 결정 기록이 들어 있다. 다른 파일 없이 검토·수정할 수 있다.
- 가장 먼저 볼 곳은 연출 기획서의 「부록 F 회사 데이터 연결」(연결 지점 표, 이름 대응표)이다. 기획서는 본문(무엇을 만드는지)과 부록(어떻게 만드는지)으로 나뉜다.

## 게임 맥락

대상: 카오스 제로 나이트메어. 기획자가 직접 알려준 회사 정보만 적는다(나머지는 모른다).

| 항목 | 내용 |
|---|---|
| 스토리 기능 | 자동 진행, 배속(켬/끔 두 가지, 배율 미확인), 다시보기, 대사 로그가 있다 |
| 스토리 화면 | 가로 화면 |
| 시간·글자 | 회사 데이터는 시간에 ms, 글자에 문자열 테이블 키를 쓴다 |
| Actor 테이블 | 회사에 Actor 테이블이 있고 이름과 리소스 경로를 가져올 수 있다 |
| 스토리 테이블 | 한 행에 `id`가 있고 옆으로 열이 늘어선다(쓸 배경, 텍스트 타입, 쓸 액터 등). 내보내면 한 행이 `{}` |
| 테이블 규칙 | 행마다 `id`. key도 쓸 수 있다. 그룹은 쓰지 않는다. 다른 테이블 id 참조는 `link_*_id`. 열 이름은 소문자 + 밑줄 |
| 부모-자식 | 자식 행이 자기 id를 갖는 것이 기본. 부모가 자식의 key를 읽거나 자식이 부모 id를 본다. 프로그램실은 key를 읽는 쪽을 권장 (정확한 형식은 기획자도 확인 필요) |
| 데이터 원본 | 테이블은 엑셀. 연출 데이터는 JSON인 경우도 있다 |

# 기획서 전문 1: 스토리 맵 핀 이동 연출 (v0.19 회사 검토용)

> 스토리 진행 중 배경 지도 위에서 핀(캐릭터·대상)이 경로를 따라 이동하며 "누가 어디서 어디로 갔는지"를 보여주는 연출 기능.

### 개요

스토리 대사 사이에 배경 지도 한 장을 깔고, 장소 이름과 핀(캐릭터나 함대 같은 대상)을 올려 정해진 경로로 움직인다. 유저는 글을 읽지 않아도 누가 어디서 어디로 갔는지 알 수 있다.

- **목표**: "누가 어디서 어디로 갔는지 한 번에 읽힌다."
- **쓰는 곳**: 메인 스토리에서 이동이 중요한 장면에 가끔 쓴다. 한 번에 8초 안쪽으로 짧게 끝난다.
- **만드는 법**: 스토리 기획자가 편집 툴에서 배경을 고르고, 장소 이름을 새기고, 핀마다 Actor와 경로를 정한다. 스토리 테이블의 행에서 연출 id로 맵을 열고 닫는다.
- **이번 범위가 아닌 것**: 카메라 이동, 유저가 핀을 조작하는 기능, 전투·탐험 화면의 지도.
- **읽는 법**: 본문은 무엇을 만드는지, 부록은 어떻게 만드는지(데이터, 수치, 계산식, 예외, 검수, 구현 규칙)다. 배지가 없는 항목은 확정이고, `검증필요`·`미정`만 배지로 표시한다. 테이블·키 이름과 수치는 자리표시다. 용어와 담당별 읽을 곳은 부록 K, 아트·사운드 요청은 부록 L, 프로그램실 회의 안건은 부록 F 끝에 있다.

메인 스토리에서 이동이 중요한 순간에 가끔 나온다. 유저는 직전 대사로 "누가 어디로 가는지" 듣고, 지도에서 그 이동을 눈으로 확인한 뒤 다음 대사로 돌아온다. 아래는 예시 연출 두 개(장면 1, 장면 2)를 게임 화면 그대로 그린 것이다. 배경과 인물은 자리표시다.

유저가 읽는 순서:

1. **직전 대사**: 누가 어디로 갈지 듣는다.
2. **장소 이름**: 지도가 나타나면 장소 이름이 먼저 읽힌다. 이야기에 나오는 장소만 보인다.
3. **출발**: 핀이 움직이기 시작하고 효과음이 한 번 난다. 핀이 여럿이면 시차를 두고 출발한다.
4. **궤적**: 지나온 길만 점선으로 남아, 끝난 뒤에도 "어디서 왔는지"가 보인다.
5. **도착과 대사**: 대사창이 돌아와도 도착 지점은 가려지지 않는다. 지도는 닫힐 때까지 대사 뒤에 남는다.

화면 탭 한 번으로 언제든 끝 상태로 넘길 수 있다.

시간으로 보면, 배경과 핀이 400ms씩 나타난 뒤 0ms에 이동을 시작하고, 마지막 도착 1000ms 뒤에 끝난다. 열린 맵에서 이어지는 연출은 나타나는 단계 없이 바로 시작한다. 전체 상태 전이표는 부록 J에 있다.

### 부록 A. 데이터 설계

> **설계 원칙**
>
> - **엑셀과 JSON을 나눈다**: 사람이 손으로 고치거나 다른 테이블과 이어지는 것(배경, 장소, 연출 머리, 속도 프리셋, 설정)은 엑셀 테이블에 둔다. 툴이 만드는 것(핀, 경로 점, 장소 보임)은 연출 1건당 JSON 1개에 둔다.
> - **회사 테이블 규칙**: 행마다 `id`, 다른 테이블 참조는 `link_*_id`, 열 이름은 소문자 + 밑줄, 그룹 id는 쓰지 않는다.
> - **사람이 읽는 값**: 좌표는 배경 픽셀 정수, 시간은 ms 정수, 글자는 문자열 키, 선택지는 영문 대문자 열거값.
> - **비워 두면 기본값**: 엑셀은 칸을 비우고, JSON은 필드를 생략하면 기본값을 쓴다.
> - **복사본 없음**: 같은 값을 두 곳에 두지 않는다. 장소 좌표는 장소 테이블에만, 이어가기 시작 위치는 앞 연출에만 있다.
> - 테이블·열·필드 이름과 id 숫자는 모두 자리표시다. `검증필요`

#### 연출 JSON

연출 하나가 파일 하나다. 기본값인 필드는 생략한다.

| 필드 | 형식 | 기본값 | 설명 |
|---|---|---|---|
| `version` | int | (필수) | 형식 버전. 지금은 1 |
| `id` | int | (필수) | `map_scene.id`와 같아야 한다. 파일이 바뀌지 않았는지 확인하는 용도 |
| `show_prev_trail` | bool | true | 앞 궤적을 흐리게 표시(R-25) |
| `outro_ms` | int | `MAP_OUTRO_MS` | 마무리 대기 |
| `places` | 목록 | 빈 목록 | 장소 마크 보임/숨김 |
| `places[].place_id` | int | (필수) | `map_place.id`. 연출의 배경에 속한 장소여야 한다 |
| `places[].visible` | bool | (필수) | 보임 / 숨김 |
| `pins` | 목록 | (필수) | 핀 목록 |

핀 하나(`pins[]`):

| 필드 | 형식 | 기본값 | 설명 |
|---|---|---|---|
| `pin_no` | int | (필수) | 핀 번호 1부터. 이어가기 연출 사이에서 같은 번호가 같은 핀 |
| `actor_id` | int | (필수) | Actor 테이블 id. 이름·리소스 경로를 여기서 가져온다 (R-33) |
| `show_from` | enum | `START` | `START` / `ON_DEPART` (R-42) |
| `label_key` | string | (없음) | 이름표 문자열 키. 없으면 Actor 이름 |
| `show_label` | bool | true | 이름표 표시 |
| `speed_preset_id` | int | 1 | `map_speed_preset.id`. `duration_ms`가 있으면 무시 |
| `duration_ms` | int | (없음) | 이동 시간 직접 고정 |
| `start_type` | enum | `TIME` | `TIME` / `AFTER_ARRIVE` |
| `start_pin_no` | int | (없음) | 기준 핀 번호 (`TIME`이면 없음) |
| `start_offset_ms` | int | 0 | 기준점에서 몇 ms 뒤에 출발하는지. 기준점은 `TIME`이면 0ms(이동 시작), 아니면 기준 핀의 출발·도착 시각 |
| `curve` | enum | `SMOOTH` | `SMOOTH` / `LINE` |
| `waypoints` | 목록 | 빈 목록 | 경로 점. 적힌 순서가 지나는 순서다 |

웨이포인트 하나(`waypoints[]`):

| 필드 | 형식 | 설명 |
|---|---|---|
| `place_id` | int | 장소를 가리키면 장소 id. 이 경우 `x`, `y`는 적지 않는다 |
| `x`, `y` | int | 배경 px. `place_id`가 없을 때만 |
| `in_x`, `in_y` | int | 들어오는 쪽 베지어 핸들. 점 기준 상대 px. 없으면 자동 곡선 |
| `out_x`, `out_y` | int | 나가는 쪽 베지어 핸들. 점 기준 상대 px. 없으면 자동 곡선 |

- 일반 핀은 첫 웨이포인트가 시작점이다. 이어가기 연출에서 앞 연출과 같은 번호의 핀은 시작점이 앞 연출에서 오므로 첫 웨이포인트가 첫 목적지다(R-23).
- 이어가기 연출에서 앞 연출과 같은 번호의 핀은 `actor_id`도 앞 연출과 같아야 한다. 툴이 채우고 바꾸지 못하게 한다.
- 웨이포인트가 시작점 하나뿐이면(또는 이어진 핀에 웨이포인트가 없으면) 이동 없이 위치만 보여준다(R-29).
- 핸들은 점 기준 상대값이라 장소를 옮겨도 곡선 모양이 유지된다. 핸들 한쪽만 적으면 반대쪽은 자동이다. `curve`가 `LINE`이면 핸들은 무시한다.
- 장소 보임(`places`): 일반 연출은 `visible`이 true인 마크만 보인다. 이어가기 연출은 앞 연출 끝에 보이던 마크는 적지 않아도 보이고, 새로 보일 마크(true)와 숨길 마크(false)만 적는다.

#### map_speed_preset (속도 프리셋)

| `id` | `name` | `speed_px` | `memo` |
|---|---|---|---|
| 1 | 걷기 | 500 | 인물 기본 |
| 2 | 달리기 | 800 | 급한 이동 |
| 3 | 고속 | 1200 | 함선·비행 |

- `name`은 툴에만 보이는 이름이라 문자열 키를 쓰지 않는다.
- 속도 단위는 **배경 px/초**다(배경은 2048×1152 고정). 값은 시작값이고 실제 연출을 만들며 조정한다.

#### 왜 이렇게 나눴나

| 판단 | 이유 |
|---|---|
| 핀·웨이포인트를 JSON으로 | 회사 테이블은 그룹 id를 쓰지 않고 행마다 id가 필요하다. 점 하나마다 id를 붙여 엑셀에 늘어놓으면 손으로 관리할 수 없다. 툴이 통째로 쓰고 읽는 데이터라 JSON이 맞다 |
| 배경·장소는 엑셀로 | 장소 이름은 문자열 키로 번역되고, 여러 연출이 같은 장소 id를 가리킨다. 사람이 표로 보고 고칠 일이 있다 |
| 연출 머리(`map_scene`)를 엑셀에 | 스토리 행이 `link_map_scene_id`로 가리킬 id가 테이블에 있어야 한다. 배경과 앞 연출도 다른 행을 가리키는 연결이라 `link_*_id`로 둔다 |
| 장소 보임을 연출 JSON에 | 연출마다 달라지는 값이고 툴에서 체크로 고른다. 이어가기는 바뀐 것만 적어서 중복이 없다 |
| 핀은 번호(`pin_no`)로 식별 | 이어가기 연결 안에서 같은 핀을 번호로 이어 붙인다. 같은 Actor 핀이 둘이어도 헷갈리지 않는다 |
| 웨이포인트는 순서 번호 없이 목록 순서로 | 점을 끼워 넣어도 번호를 다시 매길 필요가 없다 |
| 속도를 프리셋으로 | "걷기가 느리다"는 피드백을 프리셋 값 하나로 모든 연출에 반영한다. 특별한 장면만 `duration_ms`로 고정한다 |
| 필드 하나에 뜻 하나 | `start_offset_ms`는 항상 "기준점에서 몇 ms 뒤"다. 기준점이 무엇인지는 `start_type`이 정한다 |
| JSON 안의 id 참조 | `actor_id`, `place_id`, `speed_preset_id`는 엑셀 검사가 닿지 않는다. 툴 저장 전 검사와 빌드 검사로 막는다(「부록 G 구현 전달사항」) |

### 부록 C. 계산 규칙

게임과 툴 미리보기가 같은 화면을 내려면 같은 식을 써야 한다. 프로토타입이 이 식 그대로 동작한다. 식 자체는 제안이고, 엔진에 같은 결과를 내는 기능이 있으면 그것을 써도 된다.

| ID | 항목 | 식 | 상태 |
|---|---|---|---|
| F-01 | 화면 배치 | 화면 안에 16:9 영역을 가운데에 가장 크게 잡는다(전체가 보이게). 화면 좌표 = 영역 원점 + 배경 px × (영역 폭 ÷ 2048). | {검증필요} |
| F-02 | 곡선 (`SMOOTH`) | 점 i에서 i+1까지를 3차 베지어로 잇는다. 제어점은 P[i] + out[i], P[i+1] + in[i+1]. 핸들이 없는 점은 out[i] = (P[i+1] − P[i−1]) ÷ 6, in[i] = −out[i]를 쓴다. 양 끝 점은 없는 이웃 대신 자기 자신을 쓴다. (Catmull-Rom과 같은 모양) | {검증필요} |
| F-03 | 직선 (`LINE`) | 점과 점을 직선으로 잇는다. 핸들은 무시한다. | {확정} |
| F-04 | 경로 길이 | 곡선은 구간마다 16등분한 점을 직선으로 이은 길이의 합. 단위는 배경 px. | {검증필요} |
| F-05 | 이동 시간 | 이동 시간 = 길이 ÷ 프리셋 `speed_px` × 1000을 100ms 단위로 반올림하고, 최소 100ms. `duration_ms`가 있으면 그 값을 쓴다. 점이 하나뿐이거나 길이가 0이면 이동 없음. | {검증필요} |
| F-06 | 출발 시각 | `TIME`: 오프셋. `AFTER_ARRIVE`: 기준 핀 도착 시각(출발 + 이동 시간) + 오프셋. 기준 핀이 이동 없는 핀이면 도착 시각 = 출발 시각. | {확정} |
| F-07 | 진행 | u = (지금 − 출발) ÷ 이동 시간을 0~1로 자른다. 천천히 출발·도착: u < 0.5면 2u², 아니면 1 − (2 − 2u)² ÷ 2. 핀 위치는 경로 길이의 그 비율 지점(거리 기준). | {검증필요} |
| F-08 | 연출 길이 | 등장 = 열린 맵에서 이어지면 0, 아니면 `MAP_FADE_MS` × 2(배경 다음 핀). 이동 끝 = 가장 늦은 도착 시각. 종료 = 이동 끝 + 마무리 대기(연출의 `outro_ms`, 없으면 `MAP_OUTRO_MS`). | {확정} |
| F-09 | 겹침 벌리기 | 쉬는 핀끼리 화면 거리가 핀 지름 × 0.9보다 가까우면 한 무리다. 무리의 중심은 평균 위치. 간격은 핀 지름 × 1.15와 (무리에서 가장 긴 이름표 폭 + 6px) 중 큰 값. 원래 x가 작은 핀부터, 같으면 핀 번호 순으로 왼쪽에서 오른쪽으로 놓는다. k번째 핀의 x = 중심 + (k − (n − 1) ÷ 2) × 간격. 묶음이 바뀌면 그 프레임에 바로 새 자리를 쓴다(보간 없음). | {검증필요} |
| F-10 | 이어가기 시작 상태 | 맨 앞 연출부터 차례로 따라가며 계산한다. ① 핀 위치: 핀 번호마다 가장 마지막에 나온 연출의 끝 위치(목록에서 빠진 핀은 없음). ② 장소 마크: 연출마다 보임 목록을 더하고 숨김 목록을 뺀 결과. ③ 앞 궤적: 바로 앞 연출의 경로(R-56). | {확정} |
| F-11 | 탭 완료 | 탭한 순간의 연출 시각을 t0라 하면, 표시 시각 = t0 + (종료 − t0) × (탭 뒤 지난 시간 ÷ `MAP_TAP_FINISH_MS`). | {확정} |
| F-12 | 방향 표시 | 이동 중인 핀의 삼각형은 지금 구간의 진행 방향을 가리킨다. 쉬는 핀에는 삼각형이 없다. | {확정} |
| F-13 | 표시 크기 | 화면에 그리는 크기 = max(최솟값, UI px 값 × 화면 높이 ÷ `MAP_UI_BASE_HEIGHT`). 핀 지름·이름표 글자·장소 글자에만 최솟값이 있다(R-57). | {검증필요} |

### 부록 D. 예시 연출과 데이터

아래 타임라인과 데이터는 같은 예시(장면 1, 장면 2)다. 프로토타입 첫 화면도 이 두 연출이다.

#### 타임라인

캐릭터와 장소 이름은 자리표시다.

- 총 길이: 장면 1은 등장 800ms + 이동 3200ms + 마무리 1000ms = 5000ms, 장면 2(열린 맵에서 이어짐)는 이동 2800ms + 마무리 1000ms = 3800ms
- 건너뛰기: 화면 탭으로 즉시 완료(R-12). 다시보기와 대사 로그에서 다시 재생 가능(R-14, R-35)

|---:|---:|---|---|---|
| -800 | 400 | 배경·장소 마크 | 페이드인 | MAP_FADE_MS |
| -400 | 400 | 핀 1·2·3 | 시작 위치에서 페이드인 | MAP_FADE_MS |

### 부록 G. 구현 전달사항

프로그래머에게 전하는 제안이다. 더 나은 방법이 있으면 바꿔도 되고, 화면 결과만 「부록 C 계산 규칙」과 같으면 된다.

- **시각 하나로 화면을 계산한다**: "연출 데이터 + 연출 시각 t → 배경 불투명도, 장소별 불투명도, 핀별 위치·불투명도·방향, 궤적 길이"를 돌려주는 함수 하나로 만든다. 탭 완료(R-53), 배속(R-54), 툴의 시간 이동, 로그 다시 재생(R-45), 세이브 복원이 모두 t만 바꾸면 해결된다. 겹침 정렬도 t 하나로 계산하므로 프레임 사이 상태가 없다.
- **미리 계산**: 연출을 불러올 때 경로 샘플 점, 구간 길이, 핀별 출발·도착 시각을 한 번 계산해 둔다. 이어가기는 앞 연출을 따라가 시작 상태를 계산한다(F-10).
- **설정 값은 코드에 적지 않는다**: 모든 수치는 설정 키에서 읽는다. 값을 바꾸고 다시 빌드하지 않고 확인할 수 있으면 좋다.
- **폰 최소 크기**: 핀·이름표·장소 글자는 F-13의 최솟값 아래로 줄이지 않는다. 폰 가로 화면에서 가장 먼저 깨지는 곳이다.
- **궤적은 코드로 그린다**: 리소스 없이 핀 색의 둥근 점선을 그린다. 두께와 간격은 UI px 설정 값이다.
- **미리 불러오기**: 스토리에 들어갈 때 그 스토리 행들이 가리키는 연출의 배경과 핀 아이콘을 미리 불러온다. 재생 순간에 멈칫하지 않게 한다. `검증필요`
- **데이터 검사**: 연출 JSON 안의 `actor_id`, `place_id`, `speed_preset_id`는 엑셀 검사가 닿지 않는다. 툴의 저장 전 검사(툴 기획서 T-07)와 같은 규칙으로 빌드 때 한 번 더 검사하는 스크립트를 둔다. 손으로 고친 JSON도 걸러진다.
- **JSON 형식 버전**: `version`이 아는 값이 아니면 연출을 건너뛰고 로그를 남긴다. 형식을 바꿀 때 버전을 올린다.
- **세이브**: 스토리 중간 저장이 있다면 "지금 열린 연출 id" 하나만 저장한다. 복원할 때 그 연출의 최종 상태를 계산해 바로 유지 상태로 띄운다.
- **확인용 기능**: 연출 id를 넣으면 스토리 없이 바로 재생하는 개발용 명령이 있으면 기획·QA 확인이 빨라진다.
- **로그**: 「부록 E 예외 처리」의 모든 줄은 연출 id와 핀 번호를 담은 로그를 남긴다.

#### 이어가기 세부

연속된 이동을 여러 연출로 나눠 대사 사이에 끼워 넣기 위한 기능이다. 예를 들어 "A가 관측소로 간다 → 대사 → A가 탑으로 간다"를 두 연출로 만든다.

- 이어가기 연출은 **앞 연출 id만** 가진다. 다음 값은 저장하지 않고 앞 연출 데이터를 따라가며 계산한다(계산 순서는 부록 C의 F-10).
  - 시작 위치: 앞 연출과 같은 번호의 핀은 앞 연출에서 그 핀이 끝난 위치
  - 앞 궤적: 바로 앞 연출의 경로(R-56)
  - 장소 마크: 앞 연출 끝에 보이던 마크는 계속 보인다. 이 연출의 장소 목록에는 **새로 보일 마크와 숨길 마크만** 적는다.
- 앞 연출을 고치면 뒤 연출의 시작 위치도 자동으로 따라간다. 툴은 영향받는 뒤 연출 수를 알려준다.
- 다른 연출이 참조 중인 연출은 툴에서 지울 수 없다.
- 앞 연출에 없던 핀을 추가하면 그 핀만 일반 등장(400ms 페이드인)한다.
- 앞 연출에 있던 핀을 이 연출의 핀 목록에서 빼면 그 핀은 연출이 시작될 때 사라진다(R-49).
- 연출 중에는 대사가 나오지 않으므로, 이동 사이에 대사가 들어가면 연출을 나눠 이어가기로 잇는다. 대사 없이 이어지는 이동은 한 연출 안에서 출발 조건으로 잇는다.

#### 스토리 테이블 연동

회사 스토리 테이블은 한 행에 `id`가 있고 옆으로 열이 늘어선 형태이며, 내보내면 한 행이 `{}` 객체가 된다. 여기에 열 2개를 더한다. 열 이름은 자리표시다.

| 추가 열 | 형식 | 뜻 | 상태 |
|---|---|---|---|
| `link_map_scene_id` | int (비움 가능) | 이 행에서 재생할 연출의 id(`map_scene.id`). 비우면 아무 일도 없다 | {검증필요} |
| `map_close` | bool (비움 가능) | TRUE면 이 행을 시작할 때 열린 맵을 닫는다 | {검증필요} |

- 한 행의 처리 순서는 맵 닫기 → 맵 열기 → 그 행의 대사다. 대사가 없는 행이면 연출만 재생하고 다음 행으로 넘어간다.
- 편집 툴은 별도 툴이라 스토리 순서를 모른다. 게임은 "지금 열린 맵"만 보고 이어가기 여부를 판단하므로 순서 정보가 필요 없다.
- 행에 기존 배경 열 값이 있어 배경이 바뀌면 맵은 자동으로 닫힌다.

예시 흐름:

| 순서 | `link_map_scene_id` | `map_close` | 대사 | 화면 |
|---|---|---|---|---|
| 1 | 30001 | | 있음 | 맵이 열리고 장면 1 재생. 끝나면 대사 |
| 2 | | | 있음 | 맵은 대사 뒤 배경으로 남음 |
| 3 | 30002 | | 있음 | 장면 1의 맵이 열려 있으므로 페이드인 없이 장면 2 재생. 끝나면 대사 |
| 4 | | | 있음 | 맵은 계속 배경 |
| 5 | | TRUE | 있음 | 400ms 동안 맵을 닫고 원래 스토리 배경에서 대사 |

내보낸 행의 모양(기존 열은 생략):

```json
{ "id": 310105, "link_map_scene_id": 30001 }
{ "id": 310109, "map_close": true }
```

# 기획서 전문 2: 맵 이동 연출 편집 툴 (v0.19 회사 검토용)

> 기획자가 「스토리 맵 핀 이동 연출」을 만드는 툴. 경로 그리기, 장소 마크, 앞 연출에서 이어가기, 미리보기, 데이터 저장을 다룬다.

### 개요

「스토리 맵 핀 이동 연출」(`plans/story-map-pin-move/`)의 데이터를 만드는 편집 툴이다. 연출 규칙(R-xx), 계산식(F-xx), 데이터 형식은 그 기획서(이하 "연출 기획서")를 따르고, 이 문서는 **툴에서 어떻게 만드는지**만 다룬다.

- **사용자**: 스토리 연출을 만드는 기획자 여러 명. 처음 쓰는 사람도 헷갈리지 않고, 사람마다 만든 연출의 품질이 비슷해야 한다. 같은 배경과 장소를 여러 사람이 나눠 쓰며, 회사에서는 파일 잠금(락)과 기존 협업 규칙(id, 이름)으로 충돌을 막는다.
- **대상 기기**: PC(마우스와 키보드). 프로토타입이 폰 터치로도 조작되는 것은 기획 검토를 폰에서 하기 위한 것이고, 툴 요구가 아니다. 터치 기기 지원이 필요해지면 더블탭과 길게 누르기를 같은 규칙으로 쓴다. `검증필요`
- **목표**: 연출 하나를 5분 안에 만든다. 점 몇 개를 찍으면 곡선이 나오고, 앞 연출에서 이어갈 때는 버튼 하나로 시작 상태가 채워진다. `검증필요`
- **원칙**: 툴에서 보는 미리보기와 게임 화면이 같아야 한다. 같은 계산식(연출 기획서 「부록 C 계산 규칙」)을 쓴다.
- **결과물**: 연출 1건당 JSON 1개와 엑셀 테이블 행(`map_scene`, `map_place`, `map_background`). 형식은 연출 기획서 「부록 A 데이터 설계」에 있다.
- **단위**: 툴 화면의 좌표·길이는 배경 px, 시간은 ms, 속도는 px/초로 표시한다.
- 동작 프로토타입(`plans/story-map-pin-move/proto/`)의 「편집 툴」 탭이 이 문서의 주요 기능을, 「데이터」 탭이 저장 형식을 구현해 두었다.
- 회사 확인, 프로그램실 회의 안건 같은 남은 일은 「부록 F 검증·미결 목록」에 있다.
- 기획자용 조작 안내와 「좋은 연출 기준」은 `plans/map-move-tool/guide.md`에 있다. 기준의 원본은 연출 기획서 「연출 작성 기준」이고, 툴은 그 기준을 경고로 알려준다(CK-13, CK-14, CK-18~CK-20).
- 이 문서는 회사 밖에서 회사 데이터 없이 썼다. 테이블·열·필드 이름은 자리표시다.

### 경로 그리기

경로는 **점(웨이포인트)을 찍어서** 만든다. 직선·곡선은 그리는 방법이 아니라 경로의 속성이다. 같은 점으로 직선과 곡선을 오가며 비교할 수 있다.

#### 그리기 방식

| ID | 방식 | 동작 | 상태 |
|---|---|---|---|
| P-01 | 점 찍기 | 빈 곳을 더블클릭할 때마다 선택한 핀의 경로 끝에 점을 추가한다. | {확정} |
| P-02 | 자유 그리기 | 이번 버전에서 제외한다. 프로그램실 회의에서 필요 여부를 확인한다. | {미정} |

#### 경로 형태

| ID | 형태 | 설명 | 상태 |
|---|---|---|---|
| P-03 | 곡선 (기본) | 점만 찍으면 모든 점을 지나는 부드러운 곡선(Catmull-Rom)이 자동으로 나온다. 모양을 더 잡고 싶은 점에서만 베지어 핸들을 꺼낸다. | {확정} |
| P-04 | 직선 | 점과 점을 직선으로 잇는다. 길·복도처럼 꺾이는 이동에 쓴다. | {확정} |
| P-05 | 구간별 형태 | 한 경로 안에서 구간마다 직선/곡선을 다르게 지정할지. 점별 핸들로 대부분 해결되므로 이번 버전은 넣지 않는다. | {확정} |

> **곡선 방식: 자동 곡선 + 필요한 점만 베지어 핸들**
>
> 모든 점에 베지어 핸들을 두면 모양은 정확하지만 점마다 손이 간다. 자동 곡선(Catmull-Rom)은 점만 찍으면 되지만 모양을 세밀하게 잡기 어렵다. 그래서 기본은 자동 곡선으로 빠르게 만들고, 모양이 마음에 들지 않는 점에서만 핸들을 꺼내 다듬는다. 자동 곡선은 내부적으로 핸들을 자동 계산한 베지어와 같으므로(연출 F-02), 핸들을 꺼내는 순간 모양이 바뀌지 않고 그 자리에서 조절이 시작된다.

### 부록 E. 편집 조작 세부

편집 화면에서 "고르려고 눌렀는데 점이 찍히는" 실수를 막는 규칙이다. **한 번 누르기는 선택, 더블클릭은 생성**으로 나눈다. 도구를 바꿀 필요가 없다. 모든 규칙은 프로토타입 「편집 툴」 탭에 구현되어 있다.

| ID | 요구 | 상태 |
|---|---|---|
| E-01 | **생성은 더블클릭**: 점과 장소 마크는 더블클릭(같은 자리 10px 안에서 350ms 안)으로만 생긴다. 한 번 누르기는 선택만 한다. | {확정} |
| E-02 | **누르기 우선순위**: 선택한 점의 핸들 → 선택한 핀의 점 → 핀 본체 → 다른 핀의 점 → (더블클릭일 때) 점 추가 → 경로 선 → 빈 곳. 다른 핀이나 그 핀의 점을 누르면 그 핀을 선택할 뿐이다. | {확정} |
| E-03 | **끌기 문턱**: 6px 이상 움직여야 끌기로 본다. 그보다 작게 움직인 누르기는 선택만 하고, 실행 취소 기록에도 남지 않는다. | {확정} |
| E-05 | **빈 곳과 경로 선**: 한 번 누르면 빈 곳은 선택 해제, 경로 선은 그 핀 선택. 더블클릭하면 빈 곳은 선택한 핀의 끝에 점 추가, 선택한 핀의 경로 선 위는 그 자리에 끼워 넣기. | {확정} |
| E-06 | **조작 안내는 문서로**: 툴 안에 조작 안내를 띄우지 않고 사용 안내 문서(`guide.md`)로 대신한다. 계속 쓰는 툴이라 반복 안내는 방해가 된다. `Esc`는 선택을 푼다. | {확정} |
| E-07 | **재생 중 입력**: 편집 보기에서 재생 중에 캔버스를 누르면 일시정지만 하고 편집하지 않는다. | {확정} |
| E-08 | **되돌리기 안내 없음**: 점 추가·끼워 넣기·삭제 뒤 되돌리기 안내를 띄우지 않는다. 실행 취소 버튼과 `Ctrl+Z`만 둔다. | {확정} |
| E-10 | **누른 대상으로 편집 전환**: 핀·경로 편집 중 장소를 한 번 누르면 장소 편집으로, 장소 편집 중 핀이나 점을 누르면 핀·경로 편집으로 바뀐다. 장소 위 더블클릭(점 추가)과 구분하려고 350ms 뒤에 바꾼다. | {확정} |
| E-11 | **겹칠 때 우선순위**: 핀·경로 편집에서는 핀·점이 장소보다 먼저 잡힌다. 장소 편집에서는 장소 이름 → 핀 → 점 → 장소 점 순서다. | {확정} |

### 결정 기록: 맵 이동 연출 편집 툴

### 게임 맥락
- 대상: 카오스 제로 나이트메어. `docs/game-context.md`, `plans/story-map-pin-move/decisions.md` 참고.
- 이 툴은 「스토리 맵 핀 이동 연출」의 데이터를 만든다.

### 확정
- 툴에서는 앞으로 갈 경로와 도착 지점이 보인다. (V-01)
- 툴에서 앞 연출의 끝 상태를 쉽게 가져올 수 있어야 한다. (C-01)
- 경로 그리기 방법(직선, 곡선 등)을 정리한다. 양이 많아 연출 기획서와 분리했다.

- 기존 스토리 툴과 분리된 별도 툴로 만든다. (T-08, 2026-11-08)
- 장소 마크 세트는 기획이 툴에서 관리한다. (M-03, 2026-11-08)

- 편집 모드에서 점·장소 생성은 더블클릭만. 한 번 누르기는 선택. (E-01, 2026-11-11)

- 장소를 누르면 장소 편집으로, 핀·점을 누르면 핀·경로 편집으로 자동 전환. 장소 위 더블클릭은 장소에 붙은 점 추가. (E-10, 2026-11-11)

- 저장 형식은 연출 JSON + 엑셀 행. 툴 대상 기기는 PC로 적되 `검증필요`. (2026-11-15)
- E-02, E-11 누르기 우선순위는 지금 순서, E-03 끌기 문턱 6px, E-05 빈 곳·경로 선 동작, E-07 재생 중 누르면 일시정지만. (2026-11-16)
- E-06 툴 안에서 조작 안내 문구를 띄우지 않는다. 계속 쓰는 툴이라 조작법은 별도 사용 안내 문서(`guide.md`)로 해결한다. (2026-11-16)
- E-08 되돌리기 안내는 띄우지 않는다. (2026-11-16)
- M-07 배경을 해상도가 다른 파일로 바꾸면 물어보고 비율 변환한다. (2026-11-16)

- 회사는 툴 데이터를 파일 잠금(락)을 잡고 편집하고, id·이름 협업 규칙이 이미 있다. 그래서 공유 장소 변경 확인(M-09)과 묶음 이름 규칙(S-07)은 넣지 않고, id는 회사 채번 규칙(D-05), 동시 편집은 파일 잠금(D-07)으로 한다. (2026-11-21)
- 연출 작성 기준 경고 CK-18~CK-20을 둔다. (2026-11-21)

- 출발 조건은 시간 / 다른 핀 도착 후 두 가지(K-04). 이어가기 핀은 자동으로 앞 끝 위치에서 출발(C-02, P-10). (2026-11-21)

- 2차 복잡성 검토: 이징·궤적·도착 후·핀 색 항목 삭제(K-08, C-06, CK-05 삭제), 고급 옵션 접기(K-09), 단축키는 부록 D로. (2026-11-21)

- 3차 정리: 배경 2048×1152 고정으로 M-07 삭제, 장소 이름 글자 수 제한 삭제(M-05), 글자 겹침 경고 확대(CK-17), 편집 조작 세부는 부록 E, 검증·미결은 부록 F. (2026-11-21)

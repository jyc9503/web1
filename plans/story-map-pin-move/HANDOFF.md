# 스토리 맵 핀 이동 연출 + 편집 툴 회사 검토 요청 (연출 v0.28 / 툴 v0.28)

## 이 문서가 무엇인가

스토리 대사 사이에 배경 지도 위에서 핀(캐릭터·대상)이 경로를 따라 움직여 "누가 어디서 어디로 갔는지"를 보여주는 연출 기능과, 그 데이터를 만드는 편집 툴의 기획서다. 규칙·데이터 설계·프로토타입까지 끝났고, 회사 데이터에 맞추는 단계만 남았다.

- **이 기획은 회사 외부에서 회사 데이터 없이 작성되었다.** 테이블·열·필드·키 이름과 id 숫자는 모두 자리표시다.
- **본 문서는 바로 아래 「핵심 기획서」다.** 기능을 이해하려면 이것만 읽으면 된다. 그 뒤의 두 기획서 전문은 데이터·계산식·예외·툴 세부를 담은 참고 자료다.
- 이 파일 하나에 핵심 기획서, 두 기획서 전문, 결정 기록이 들어 있다. 다른 파일 없이 검토·수정할 수 있다.
- 회사 데이터와 맞출 때 가장 먼저 볼 곳은 연출 기획서의 「부록 F 회사 데이터 연결」(연결 지점 표, 이름 대응표)이다.

## 핵심 기획서 (먼저 이것만 읽는다, v0.28)

> 스토리 중에 지도가 열리고, 핀이 경로를 따라 움직여 "누가 어디서 어디로 갔는지"를 보여준다. 회사에 내는 짧은 본 문서다.

### 무엇을 왜 만드나

스토리 대사 사이에 지도 한 장을 깔고, 장소 이름과 핀(캐릭터나 함대 같은 대상)을 올려 정해진 길로 움직인다.

- **목표**: 누가 어디서 어디로 갔는지 한 번에 읽힌다. 글로 설명하던 이동을 눈으로 보여준다.
- **쓰는 곳**: 메인 스토리에서 이동이 중요한 장면에 가끔 쓴다.
- **범위가 아닌 것**: 카메라 이동, 유저가 핀을 조작하는 기능, 전투·탐험 화면의 지도.

이 문서만 읽으면 기능을 이해할 수 있다. 데이터, 계산식, 예외, 툴 세부는 「참고 자료」에 있고 필요할 때만 연다.

### 플레이어가 보는 장면

1. 지도가 나타나면 장소 이름이 먼저 읽힌다.
2. 핀이 출발하고 효과음이 한 번 난다.
3. 지나온 길이 점선으로 남아, 끝난 뒤에도 어디서 왔는지 보인다.
4. 대사가 돌아와도 지도는 대사 뒤에 남는다. 탭 한 번이면 언제든 끝 상태로 넘어간다.

### 핵심 규칙 12개

괄호 안은 전체 기획서의 규칙 번호다.

1. 지도 1장 위에 장소 이름과 핀을 올린다. 핀 1개는 Actor 1개다. (R-01, R-20, R-02)
2. 기획자가 핀마다 직선이나 곡선 경로를 정한다. (R-03, R-04, R-07)
3. 이동 시간은 속도(걷기·달리기 등)와 경로 길이로 자동 계산한다. (R-08)
4. 핀은 정한 시각에, 또는 다른 핀이 도착한 뒤에 출발한다. (R-38)
5. 게임 화면에는 지나온 길만 점선으로 남는다. 갈 길은 미리 보이지 않는다. (R-09)
6. 핀 아래 이름표는 Actor 이름이다. (R-10)
7. 도착한 핀은 남는다. 같은 자리에 모이면 나란히 선다. (R-11, R-17)
8. 효과음은 연출당 한 번, 첫 핀이 출발할 때 난다. (R-30)
9. 재생 중에는 대사창을 숨긴다. 끝나면 지도는 대사 뒤 배경으로 남고, 닫기 명령이 오면 닫힌다. (R-15, R-26, R-31)
10. 재생 중 탭하면 남은 이동을 빨리 감아 바로 끝낸다. (R-12, R-53)
11. 스토리의 배속, 자동 진행, 다시보기, 대사 로그를 그대로 따른다. (R-13, R-36, R-14, R-35)
12. 연출은 앞 연출이 끝난 상태에서 이어서 시작할 수 있다. (R-22, R-23)

### 기획자는 이렇게 만든다

스토리 기획자가 전용 편집 툴에서 만든다. 툴에 바라는 것은 다음과 같다.

- 배경 지도를 고르고, 장소 이름을 새긴다.
- 핀마다 Actor를 고르고, 지도를 눌러 경로 점을 찍는다.
- 툴 미리보기가 게임 화면과 같다.
- 저장 전에 깨진 데이터는 막는다.
- 모든 편집은 실행 취소할 수 있다.

### 데이터

새 엑셀 테이블은 없다. 장소는 장소 JSON에, 핀과 경로는 연출마다 연출 JSON 1개에 둔다. 툴이 화면에서 배치한 결과를 두 JSON에 바로 쓴다. 두 JSON은 배경 이미지처럼 기존 `story_resource_list`에 등록하고, 등록 id로 서로 가리킨다. 같은 배경에 장소 표기를 달리한 장소 JSON을 여러 개 둘 수 있다. 스토리 테이블에는 열 2개(`map_scene_resource_id` 맵 열기, `map_close` 맵 닫기)를 더한다. 배경 지도 크기는 2048×1152 한 가지다. 장소 이름은 비워 둘 수 있고, 이름 없는 장소는 게임에 보이지 않는 경로 기준점이다. 열과 필드 이름은 자리표시이고, 회사 규칙에 맞춰 바꾼다.

# 참고 자료 1: 스토리 맵 핀 이동 연출 전문 (v0.28 회사 검토용)

> 스토리 진행 중 배경 지도 위에서 핀(캐릭터·대상)이 경로를 따라 이동하며 "누가 어디서 어디로 갔는지"를 보여주는 연출 기능.

### 개요

스토리 대사 사이에 배경 지도 한 장을 깔고, 장소 이름과 핀(캐릭터나 함대 같은 대상)을 올려 정해진 경로로 움직인다. 유저는 글을 읽지 않아도 누가 어디서 어디로 갔는지 알 수 있다.

- **목표**: "누가 어디서 어디로 갔는지 한 번에 읽힌다."
- **쓰는 곳**: 메인 스토리에서 이동이 중요한 장면에 가끔 쓴다.
- **만드는 법**: 스토리 기획자가 편집 툴에서 배경을 고르고, 장소 이름을 새기고, 핀마다 Actor와 경로를 정한다. 스토리 테이블의 행에서 연출 id로 맵을 열고 닫는다.
- **이번 범위가 아닌 것**: 카메라 이동, 유저가 핀을 조작하는 기능, 전투·탐험 화면의 지도.
- **본 문서**: 회사에 내는 짧은 본 문서는 `core.md`(핵심 기획서)다. 이 문서는 그 참고 자료이고, 규칙 전체와 구현 세부를 담는다.
- **읽는 법**: 본문은 무엇을 만드는지, 부록은 어떻게 만드는지(데이터, 수치, 계산식, 예외, 구현 규칙)다. 배지가 없는 항목은 확정이고, `검증필요`·`미정`만 배지로 표시한다. 테이블·키 이름과 수치는 자리표시다.
- **용어**: 핀 번호는 연출 안에서 핀을 가리키는 번호이고, 이어가기로 연결된 연출 사이에서 같은 번호가 같은 핀이다. 웨이포인트는 경로를 이루는 점 하나다. 이어가기는 앞 연출이 끝난 상태에서 다음 연출을 시작하는 것이다.

### 플레이어가 보는 장면

메인 스토리에서 이동이 중요한 순간에 가끔 나온다. 유저는 직전 대사로 "누가 어디로 가는지" 듣고, 지도에서 그 이동을 눈으로 확인한 뒤 다음 대사로 돌아온다. 아래는 예시 연출 두 개(장면 1, 장면 2)를 게임 화면 그대로 그린 것이다. 배경과 인물은 자리표시다.

[[cuts:cut1.svg=① 등장 · 장면 1 0ms. 배경과 장소 이름이 먼저 보이고 핀이 출발점에 선다. 갈 길은 보이지 않는다.|cut2.svg=② 이동 · 장면 1 1500ms. 지나온 길만 점선으로 남고, 움직이는 핀에 방향 삼각형이 붙는다.|cut3.svg=③ 도착 · 장면 1 3200ms. 모두 장소에 도착했다. 1000ms 뒤 대사가 다시 나오고 지도는 대사 뒤에 남는다.|cut4.svg=④ 이어가기 · 장면 2 1800ms. 대사 뒤 지도가 닫히지 않고 바로 다음 이동이 시작된다. 앞 이동은 흐린 점선으로 남는다.]]

유저가 읽는 순서:

1. **직전 대사**: 누가 어디로 갈지 듣는다.
2. **장소 이름**: 지도가 나타나면 장소 이름이 먼저 읽힌다. 이야기에 나오는 장소만 보인다.
3. **출발**: 핀이 움직이기 시작하고 효과음이 한 번 난다.
4. **궤적**: 지나온 길만 점선으로 남아, 끝난 뒤에도 "어디서 왔는지"가 보인다.
5. **도착과 대사**: 대사창이 돌아와도 지도는 닫힐 때까지 대사 뒤에 남는다.

화면 탭 한 번으로 언제든 끝 상태로 넘길 수 있다.

시간으로 보면, 배경과 핀이 400ms씩 나타난 뒤 0ms에 이동을 시작하고, 마지막 도착 1000ms 뒤에 끝난다. 열린 맵에서 이어지는 연출은 나타나는 단계 없이 바로 시작한다.

### 부록 A. 데이터 설계

> **설계 원칙**
>
> - **새 테이블 없이 JSON 두 가지**: 툴이 화면에서 만드는 것은 JSON에 둔다. 장소는 장소 JSON(같은 배경에 여러 개 가능)에, 핀·경로 점·장소 보임은 연출마다 연출 JSON 1개에 둔다. 두 JSON은 배경 이미지처럼 기존 `story_resource_list`에 등록하고, 등록 id로 서로 가리킨다. 엑셀은 스토리 테이블에 열 2개를 더하는 것뿐이다.
> - **회사 테이블 규칙**: 다른 테이블 참조는 `link_*_id`, 열 이름은 소문자 + 밑줄을 따른다.
> - **사람이 읽는 값**: 좌표는 배경 픽셀 정수, 시간은 ms 정수, 글자는 문자열 키, 선택지는 영문 대문자 열거값.
> - **비워 두면 기본값**: 엑셀은 칸을 비우고, JSON은 필드를 생략하면 기본값을 쓴다.
> - **복사본 없음**: 같은 값을 두 곳에 두지 않는다. 장소 좌표는 장소 JSON에만, 이어가기 시작 위치는 앞 연출에만 있다.
> - 테이블·열·필드 이름과 id 숫자는 모두 자리표시다. `검증필요`

|---|---|---|---|---|
| 장소 JSON | JSON | 장소 세트 하나(배경 하나 + 장소 마크 목록) | `story_resource_list` 등록 id | 툴이 생성 |
| 연출 JSON | JSON | 연출 하나(장소 JSON, 앞 연출, 핀, 경로 점, 장소 보임) | `story_resource_list` 등록 id | 툴이 생성. 손으로 고칠 수 있음 |
| 스토리 테이블 | 엑셀 (기존) | 열 2개 추가 | 기존 `id` | 스토리 기획 |
| `story_resource_list` | 엑셀 (기존) | 리소스 하나. 맵 배경 이미지(2048×1152), 장소 JSON, 연출 JSON을 여기 등록한다 | 기존 `id` | 배경 담당, 기획 |

#### 장소 JSON (장소 세트마다 1개)

배경 하나와 그 위의 장소 마크를 모은 파일이다. 툴이 화면에서 배치한 결과를 그대로 쓴다.

- **id는 `story_resource_list` 등록 id다**: 파일 안에는 id를 적지 않는다. 연출 JSON이 `place_resource_id`로 이 id를 가리킨다.
- **같은 배경에 여러 개 둘 수 있다**: 같은 지도에 장소를 다르게 표기해야 하면 장소 JSON을 따로 만든다. 그 장소 JSON을 고른 연출끼리 장소를 함께 쓴다.

| 필드 | 형식 | 기본값 | 설명 |
|---|---|---|---|
| `story_resource_list_id` | int | (필수) | 배경 리소스. 기존 `story_resource_list`의 id |
| `memo` | string | (없음) | 툴 목록에서 같은 배경의 장소 JSON끼리 구분하는 메모 (게임에서 안 씀) |
| `places` | 목록 | 빈 목록 | 장소 마크 목록 |
| `places[].id` | int | (필수) | 장소 id. 이 장소 JSON 안에서만 겹치지 않으면 된다 |
| `places[].name_key` | string | (없음) | 장소 이름 문자열 키. 없으면 이름 없는 장소다(R-58) |
| `places[].x`, `y` | int | (필수) | 배경 px (0~2048, 0~1152) |
| `places[].memo` | string | (없음) | 기획 메모 (게임에서 안 씀) |

#### 연출 JSON

연출 하나가 파일 하나다. id는 `story_resource_list` 등록 id이고 파일 안에는 적지 않는다. 스토리 행이 이 id를 가리킨다. 기본값인 필드는 생략한다.

| 필드 | 형식 | 기본값 | 설명 |
|---|---|---|---|
| `place_resource_id` | int | (필수) | 장소 JSON의 등록 id. 배경도 여기서 정해진다. 이어가기면 앞 연출과 같아야 한다(R-43) |
| `prev_scene_resource_id` | int | (없음) | 이어가기 앞 연출의 등록 id. 없으면 일반 연출 |
| `memo` | string | (없음) | 툴 목록용 메모 (게임에서 안 씀) |
| `show_prev_trail` | bool | true | 앞 궤적을 흐리게 표시(R-25) |
| `outro_ms` | int | 1000 | 마무리 대기(ms) |
| `places` | 목록 | 빈 목록 | 장소 마크 보임/숨김 |
| `places[].place_id` | int | (필수) | 이 연출의 장소 JSON에 있는 장소 id. 이름 없는 장소는 적지 않는다 |
| `places[].visible` | bool | (필수) | 보임 / 숨김 |
| `pins` | 목록 | (필수) | 핀 목록 |

핀 하나(`pins[]`):

| 필드 | 형식 | 기본값 | 설명 |
|---|---|---|---|
| `pin_no` | int | (필수) | 핀 번호 1부터. 이어가기 연출 사이에서 같은 번호가 같은 핀 |
| `actor_id` | int | (필수) | Actor 테이블 id. 이름·리소스 경로를 여기서 가져온다 (R-33) |
| `show_from` | enum | `START` | `START` / `ON_DEPART` (R-42) |
| `label_key` | string | (없음) | 이름표 문자열 키. 없으면 Actor 이름 |
| `show_label` | bool | true | 이름표 표시 |
| `speed` | enum | `WALK` | 속도 프리셋 `WALK`(걷기) / `RUN`(달리기) / `FAST`(고속). 값은 F-05. `duration_ms`가 있으면 무시 |
| `duration_ms` | int | (없음) | 이동 시간 직접 고정 |
| `start_type` | enum | `TIME` | `TIME` / `AFTER_ARRIVE` |
| `start_pin_no` | int | (없음) | 기준 핀 번호 (`TIME`이면 없음) |
| `start_offset_ms` | int | 0 | 기준점에서 몇 ms 뒤에 출발하는지. 기준점은 `TIME`이면 0ms(이동 시작), 아니면 기준 핀의 출발·도착 시각 |
| `curve` | enum | `SMOOTH` | `SMOOTH` / `LINE` |
| `waypoints` | 목록 | 빈 목록 | 경로 점. 적힌 순서가 지나는 순서다 |

웨이포인트 하나(`waypoints[]`):

| 필드 | 형식 | 설명 |
|---|---|---|
| `place_id` | int | 장소를 가리키면 장소 id. 이 경우 `x`, `y`는 적지 않는다 |
| `x`, `y` | int | 배경 px. `place_id`가 없을 때만 |
| `in_x`, `in_y` | int | 들어오는 쪽 베지어 핸들. 점 기준 상대 px. 없으면 자동 곡선 |
| `out_x`, `out_y` | int | 나가는 쪽 베지어 핸들. 점 기준 상대 px. 없으면 자동 곡선 |

- 일반 핀은 첫 웨이포인트가 시작점이다. 이어가기 연출에서 앞 연출과 같은 번호의 핀은 시작점이 앞 연출에서 오므로 첫 웨이포인트가 첫 목적지다(R-23).
- 이어가기 연출에서 앞 연출과 같은 번호의 핀은 `actor_id`도 앞 연출과 같아야 한다. 툴이 채우고 바꾸지 못하게 한다.
- 웨이포인트가 시작점 하나뿐이면(또는 이어진 핀에 웨이포인트가 없으면) 이동 없이 위치만 보여준다(R-29).
- 핸들은 점 기준 상대값이라 장소를 옮겨도 곡선 모양이 유지된다. 핸들 한쪽만 적으면 반대쪽은 자동이다. `curve`가 `LINE`이면 핸들은 무시한다.
- 장소 보임(`places`): 일반 연출은 `visible`이 true인 마크만 보인다. 이어가기 연출은 앞 연출 끝에 보이던 마크는 적지 않아도 보이고, 새로 보일 마크(true)와 숨길 마크(false)만 적는다.

#### 왜 이렇게 나눴나

| 판단 | 이유 |
|---|---|
| 핀·웨이포인트를 JSON으로 | 회사 테이블은 그룹 id를 쓰지 않고 행마다 id가 필요하다. 점 하나마다 id를 붙여 엑셀에 늘어놓으면 손으로 관리할 수 없다. 툴이 통째로 쓰고 읽는 데이터라 JSON이 맞다 |
| 장소는 장소 JSON으로 | 장소는 툴 화면에서 배치한다. 툴이 파일을 바로 쓰므로 엑셀에 옮겨 붙이는 단계가 없다. 같은 배경에 장소 표기를 달리한 장소 JSON을 여러 개 둘 수 있고, 장소 id는 그 파일 안에서만 겹치지 않으면 된다 |
| 연출 정보를 연출 JSON 하나에 | 장소 JSON, 앞 연출, 메모까지 연출 JSON에 둔다. 스토리 행은 연출 JSON의 등록 id 하나만 가리키면 된다. 따로 관리할 엑셀이 없다 |
| 장소 보임을 연출 JSON에 | 연출마다 달라지는 값이고 툴에서 체크로 고른다. 이어가기는 바뀐 것만 적어서 중복이 없다 |
| 핀은 번호(`pin_no`)로 식별 | 이어가기 연결 안에서 같은 핀을 번호로 이어 붙인다. 같은 Actor 핀이 둘이어도 헷갈리지 않는다 |
| 웨이포인트는 순서 번호 없이 목록 순서로 | 점을 끼워 넣어도 번호를 다시 매길 필요가 없다 |
| 속도를 프리셋으로 | "걷기가 느리다"는 피드백을 프리셋 값 하나로 모든 연출에 반영한다. 프리셋 세 가지는 코드에 둔다. 특별한 장면만 `duration_ms`로 고정한다 |
| 필드 하나에 뜻 하나 | `start_offset_ms`는 항상 "기준점에서 몇 ms 뒤"다. 기준점이 무엇인지는 `start_type`이 정한다 |
| JSON 안의 id 참조 | `actor_id`, `place_id`, 등록 id는 엑셀 검사가 닿지 않는다. 툴 저장 전 검사로 막는다 |

### 부록 C. 계산 규칙

게임과 툴 미리보기는 같은 결과를 내야 한다. 아래는 보여야 할 결과이고, 계산 방법은 구현이 정한다.

| ID | 항목 | 결과 | 상태 |
|---|---|---|---|
| F-01 | 화면 배치 | 배경 전체가 보이게 화면 가운데에 가장 크게 놓는다. | {검증필요} |
| F-02 | 곡선 (`SMOOTH`) | 점을 모두 지나는 부드러운 곡선으로 잇는다. 핸들을 꺼낸 점은 핸들 모양을 따르고, 핸들을 꺼내는 순간 모양이 바뀌지 않는다. | {검증필요} |
| F-03 | 직선 (`LINE`) | 점과 점을 직선으로 잇는다. 핸들은 무시한다. | {확정} |
| F-05 | 이동 시간 | 이동 시간 = 경로 길이 ÷ 프리셋 속도(걷기 500, 달리기 800, 고속 1200 배경 px/초. 코드 상수) × 1000을 100ms 단위로 반올림하고, 최소 100ms. `duration_ms`가 있으면 그 값을 쓴다. 점이 하나뿐이거나 길이가 0이면 이동 없음. | {검증필요} |
| F-06 | 출발 시각 | `TIME`: 오프셋. `AFTER_ARRIVE`: 기준 핀 도착 시각(출발 + 이동 시간) + 오프셋. 기준 핀이 이동 없는 핀이면 도착 시각 = 출발 시각. | {확정} |
| F-07 | 진행 | 핀은 천천히 출발해 천천히 도착한다. 경로 위의 거리를 기준으로 움직인다. | {검증필요} |
| F-08 | 연출 길이 | 등장 = 열린 맵에서 이어지면 0, 아니면 400ms × 2(배경 다음 핀). 이동 끝 = 가장 늦은 도착 시각. 종료 = 이동 끝 + 마무리 대기(연출의 `outro_ms`, 없으면 1000ms). | {확정} |
| F-10 | 이어가기 시작 상태 | 맨 앞 연출부터 차례로 따라가며 계산한다. ① 핀 위치: 핀 번호마다 가장 마지막에 나온 연출의 끝 위치(목록에서 빠진 핀은 없음). ② 장소 마크: 연출마다 보임 목록을 더하고 숨김 목록을 뺀 결과. ③ 앞 궤적: 바로 앞 연출의 경로(R-56). | {확정} |
| F-11 | 탭 완료 | 탭하면 남은 이동을 300ms 동안 빨리 감아 끝 상태로 간다. | {확정} |
| F-12 | 방향 표시 | 이동 중인 핀의 삼각형은 지금 구간의 진행 방향을 가리킨다. 쉬는 핀에는 삼각형이 없다. | {확정} |

#### 이어가기 세부

연속된 이동을 여러 연출로 나눠 대사 사이에 끼워 넣기 위한 기능이다. 예를 들어 "A가 관측소로 간다 → 대사 → A가 탑으로 간다"를 두 연출로 만든다.

- 이어가기 연출은 **앞 연출 등록 id만** 가진다. 다음 값은 저장하지 않고 앞 연출 데이터를 따라가며 계산한다(계산 순서는 부록 C의 F-10).
  - 시작 위치: 앞 연출과 같은 번호의 핀은 앞 연출에서 그 핀이 끝난 위치
  - 앞 궤적: 바로 앞 연출의 경로(R-56)
  - 장소 마크: 앞 연출 끝에 보이던 마크는 계속 보인다. 이 연출의 장소 목록에는 **새로 보일 마크와 숨길 마크만** 적는다.
- 앞 연출을 고치면 뒤 연출의 시작 위치도 자동으로 따라간다. 앞 연출에서 지운 핀과 같은 번호의 뒤 연출 핀은 새 핀이 된다(R-23).
- 다른 연출이 참조 중인 연출은 툴에서 지울 수 없다.
- 앞 연출에 없던 핀을 추가하면 그 핀만 일반 등장(400ms 페이드인)한다.
- 앞 연출에 있던 핀을 이 연출의 핀 목록에서 빼면 그 핀은 연출이 시작될 때 사라진다(R-49).

#### 스토리 테이블 연동

회사 스토리 테이블은 한 행에 `id`가 있고 옆으로 열이 늘어선 형태이며, 내보내면 한 행이 `{}` 객체가 된다. 여기에 열 2개를 더한다. 열 이름은 자리표시다.

| 추가 열 | 형식 | 뜻 | 상태 |
|---|---|---|---|
| `map_scene_resource_id` | int (비움 가능) | 이 행에서 재생할 연출 JSON의 `story_resource_list` 등록 id. 비우면 아무 일도 없다 | {검증필요} |
| `map_close` | bool (비움 가능) | TRUE면 이 행을 시작할 때 열린 맵을 닫는다 | {검증필요} |

- 한 행의 처리 순서는 맵 닫기 → 맵 열기 → 그 행의 대사다. 대사가 없는 행이면 연출만 재생하고 다음 행으로 넘어간다.
- 편집 툴은 별도 툴이라 스토리 순서를 모른다. 게임은 "지금 열린 맵"만 보고 이어가기 여부를 판단하므로 순서 정보가 필요 없다.
- 행에 기존 배경 열 값이 있어 배경이 바뀌면 맵은 자동으로 닫힌다.

예시 흐름:

| 순서 | `map_scene_resource_id` | `map_close` | 대사 | 화면 |
|---|---|---|---|---|
| 1 | 30001 | | 있음 | 맵이 열리고 장면 1 재생. 끝나면 대사 |
| 2 | | | 있음 | 맵은 대사 뒤 배경으로 남음 |
| 3 | 30002 | | 있음 | 장면 1의 맵이 열려 있으므로 페이드인 없이 장면 2 재생. 끝나면 대사 |
| 4 | | | 있음 | 맵은 계속 배경 |
| 5 | | TRUE | 있음 | 400ms 동안 맵을 닫고 원래 스토리 배경에서 대사 |

내보낸 행의 모양(기존 열은 생략):

```json
{ "id": 310105, "map_scene_resource_id": 30001 }
{ "id": 310109, "map_close": true }
```

# 참고 자료 2: 맵 이동 연출 편집 툴 전문 (v0.28 회사 검토용)

> 기획자가 「스토리 맵 핀 이동 연출」을 만드는 툴. 경로 그리기, 장소 마크, 앞 연출에서 이어가기, 미리보기, 데이터 저장을 다룬다.

### 개요

「스토리 맵 핀 이동 연출」(`plans/story-map-pin-move/`)의 데이터를 만드는 편집 툴이다. 연출 규칙(R-xx), 계산식(F-xx), 데이터 형식은 그 기획서(이하 "연출 기획서")를 따르고, 이 문서는 **툴에서 어떻게 만드는지**만 다룬다.

- **사용자**: 스토리 연출을 만드는 기획자 여러 명. 같은 배경과 장소를 여러 사람이 나눠 쓰며, 회사에서는 파일 잠금(락)과 기존 협업 규칙(id, 이름)으로 충돌을 막는다.
- **대상 기기**: PC(마우스와 키보드). 프로토타입이 폰 터치로도 조작되는 것은 기획 검토를 폰에서 하기 위한 것이고, 툴 요구가 아니다. 터치 기기 지원이 필요해지면 더블탭과 길게 누르기를 같은 규칙으로 쓴다. `검증필요`
- **원칙**: 툴에서 보는 미리보기와 게임 화면이 같아야 한다. 같은 결과(연출 기획서 「부록 C 계산 규칙」)를 낸다.
- **결과물**: 연출마다 연출 JSON 1개, 장소 세트마다 장소 JSON 1개. 두 JSON은 `story_resource_list`에 등록한다. 배경도 거기서 고른다. 새 엑셀 테이블은 없다.
- **단위**: 툴 화면의 좌표·길이는 배경 px, 시간은 ms, 속도는 px/초로 표시한다.
- 동작 프로토타입(`plans/story-map-pin-move/proto/`)의 「편집 툴」 탭이 이 문서의 주요 기능을, 「데이터」 탭이 저장 형식을 구현해 두었다.
- 기능 전체를 짧게 보려면 연출의 핵심 기획서(`plans/story-map-pin-move/core.md`)를 먼저 읽는다. 이 문서는 툴 세부를 담은 참고 자료다.
- 회사 확인, 프로그램실 회의 안건 같은 남은 일은 「부록 D 검증·미결 목록」에 있다.
- 이 문서는 회사 밖에서 회사 데이터 없이 썼다. 테이블·열·필드 이름은 자리표시다.

경로는 **점(웨이포인트)을 찍어서** 만든다. 직선·곡선은 그리는 방법이 아니라 경로의 속성이다. 같은 점으로 직선과 곡선을 오가며 비교할 수 있다.

| ID | 형태 | 설명 | 상태 |
|---|---|---|---|
| P-03 | 곡선 (기본) | 점만 찍으면 모든 점을 지나는 부드러운 곡선이 자동으로 나온다. 모양을 더 잡고 싶은 점에서만 베지어 핸들을 꺼낸다. | {확정} |

| P-05 | 구간별 형태 | 한 경로 안에서 구간마다 직선/곡선을 다르게 지정할지. 점별 핸들로 대부분 해결되므로 이번 버전은 넣지 않는다. | {확정} |

> **곡선 방식: 자동 곡선 + 필요한 점만 베지어 핸들**
>
> 모든 점에 베지어 핸들을 두면 모양은 정확하지만 점마다 손이 간다. 자동 곡선은 점만 찍으면 되지만 모양을 세밀하게 잡기 어렵다. 그래서 기본은 자동 곡선으로 빠르게 만들고, 모양이 마음에 들지 않는 점에서만 핸들을 꺼내 다듬는다. 자동 곡선은 내부적으로 핸들을 자동 계산한 베지어와 같으므로(연출 F-02), 핸들을 꺼내는 순간 모양이 바뀌지 않고 그 자리에서 조절이 시작된다.

### 부록 C. 편집 조작 세부

편집 화면에서 "고르려고 눌렀는데 점이 찍히는" 실수를 막는 규칙이다. **한 번 누르기는 선택, 더블클릭은 생성**으로 나눈다. 도구를 바꿀 필요가 없다. 모든 규칙은 프로토타입 「편집 툴」 탭에 구현되어 있다.

| ID | 요구 | 상태 |
|---|---|---|
| E-01 | **생성은 더블클릭**: 점과 장소 마크는 더블클릭으로만 생긴다. 한 번 누르기는 선택만 한다. | {확정} |
| E-02 | **누르기 우선순위**: 선택한 점의 핸들 → 선택한 핀의 점 → 핀 본체 → 다른 핀의 점 → (더블클릭일 때) 점 추가 → 경로 선 → 빈 곳. 다른 핀이나 그 핀의 점을 누르면 그 핀을 선택할 뿐이다. | {확정} |
| E-03 | **끌기 문턱**: 조금 움직인 것은 끌기로 보지 않는다. 그런 누르기는 선택만 하고, 실행 취소 기록에도 남지 않는다. | {확정} |
| E-05 | **빈 곳과 경로 선**: 한 번 누르면 빈 곳은 선택 해제, 경로 선은 그 핀 선택. 더블클릭하면 빈 곳은 선택한 핀의 끝에 점 추가, 선택한 핀의 경로 선 위는 그 자리에 끼워 넣기. | {확정} |
| E-07 | **재생 중 입력**: 편집 보기에서 재생 중에 캔버스를 누르면 일시정지만 하고 편집하지 않는다. | {확정} |

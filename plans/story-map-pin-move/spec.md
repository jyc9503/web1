## 개요

스토리 대사 사이에 배경 이미지 한 장을 깔고, 그 위에 장소 이름과 핀(캐릭터나 함대 같은 대상)을 올려 정해진 경로로 이동시킨다. 유저는 글을 읽지 않아도 인물들이 어디서 어디로 움직였는지 알 수 있다.

- **목적**: 이동과 위치 정보를 시각으로 전달해 스토리 몰입을 높인다.
- **감정 중심**: 이동 및 위치 정보. 성공 기준은 "누가 어디서 어디로 갔는지 한 번에 읽힌다"이다.
- **사용 위치**: 스토리 테이블에서 연출 ID로 맵을 열고(재생) 닫는다. 맵은 닫기 명령 전까지 대사 뒤에 남고, 앞 연출이 끝난 상태에서 이어서 시작할 수도 있다.
- **기획자 작업**: 편집 툴에서 배경을 고르고, 장소 마크를 새기고, 핀마다 리소스와 경로를 지정한다. 스토리 테이블에는 열기·닫기 명령을 넣는다. 툴 상세는 별도 기획서 「맵 이동 연출 편집 툴」(`plans/map-move-tool/`)에 있다.

| 데이터 구조 | 툴 상세 (별도 기획서) |

### 용어

| 용어 | 뜻 |
|---|---|
| 연출 맵 | 이 연출 한 건. 배경 1장, 장소 마크, 핀 여러 개로 이뤄진다 |
| 핀 | 핀 규격 리소스 1개(캐릭터, 함대, 오브젝트 등)를 나타내는 표식 |
| 경로 | 핀이 지나가는 웨이포인트(점)의 순서 |
| 궤적 | 핀이 이미 지나온 구간. 게임에서는 점선으로 남는다 |
| 장소 마크 | 배경 위 특정 위치에 새긴 장소 이름 |
| 이어가기 | 앞 연출이 끝난 위치에서 다음 연출을 시작하는 것 |
| 맵 열림 | 맵 연출이 재생되었고 아직 닫기 명령을 받지 않은 상태. 대사 뒤에 배경으로 남는다 |
| 게임 보기 / 편집 보기 | 게임에서 보이는 화면 / 툴에서 편집할 때 보이는 화면 |

|---|---|---|---|

## 처리 흐름

1. 스토리 테이블의 `map_play` 명령이 연출 맵을 재생한다.
2. 일반 연출이면 배경과 장소 마크를 0.4초 동안 페이드인하고, 핀을 시작 위치에 0.4초 동안 페이드인한다.
3. 이어가기 연출이고 앞 연출의 맵이 열려 있으면 2를 건너뛰고 지금 화면 그대로 시작한다(R-24).
4. 핀마다 시작 지연이 지나면 경로를 따라 이동한다. 지난 구간은 점선 궤적으로 남는다.
5. 핀이 도착하면 설정에 따라 그 자리에 남거나 사라진다. 같은 자리에 모인 핀은 나란히 정렬한다(R-17, R-34).
6. 모든 핀이 도착하고 1.0초가 지나면 연출이 끝나고 다음 대사로 넘어간다. 맵은 `map_close` 명령 전까지 대사 뒤에 남는다(R-26).
7. 재생 중 화면을 탭하면 최종 상태로 0.3초 만에 이동한 뒤 끝난다(R-12).

## 이어가기

연속된 이동을 여러 연출로 나눠 대사 사이에 끼워 넣기 위한 기능이다. 예를 들어 "A가 관측소로 간다 → 대사 → A가 탑으로 간다"를 두 연출로 만든다.

- 툴에서 「앞 연출에서 이어가기」를 누르고 앞 연출을 고르면 배경, 장소 마크, 핀의 최종 위치, 앞 연출 궤적을 가져온다.
- 가져온 핀의 첫 점은 앞 연출의 끝 위치로 고정된다. 기획자는 다음 점만 찍으면 된다.
- 앞 연출에 없던 핀을 추가하면 그 핀만 일반 등장(0.4초 페이드인)한다.
- 앞 연출이 나중에 수정되면 툴이 경고하고 다시 가져오기를 제안한다. 게임은 항상 저장된 값으로 재생한다(R-27).
- 이어가기는 여러 번 연결할 수 있다(연출 1 → 2 → 3). 앞 연출 궤적은 연결된 모든 연출의 궤적을 쌓아서 보여준다. `검증필요`

## 스토리 테이블 연동

맵은 스토리 테이블의 명령으로 열고 닫는다. 편집 툴은 별도 툴이라 스토리 순서를 모르지만, 게임은 "지금 열린 맵"만 보고 이어가기 여부를 판단하므로 순서 정보가 필요 없다.

| 순서 | 스토리 테이블 | 화면 |
|---|---|---|
| 1 | `map_play map_move_01` | 맵이 열리고 장면 1 재생 |
| 2 | 대사 | 맵은 대사 뒤 배경으로 남음 |
| 3 | `map_play map_move_02` | 장면 1의 맵이 열려 있으므로 페이드인 없이 장면 2 재생 |
| 4 | 대사 | 맵은 계속 배경 |
| 5 | `map_close` | 0.4초 동안 맵을 닫고 원래 스토리 배경으로 |

## 데이터 구조

> **프로그래머분께**
>
> - 좌표는 배경 이미지의 왼쪽 위를 (0, 0), 오른쪽 아래를 (1, 1)로 하는 값이다.
> - 이동 위치는 경로를 따라 **거리 기준**으로 계산한다. 경로 전체 길이에서 `이징(t)` 비율만큼 간 지점이 현재 위치다. 거리는 화면 비율을 반영해 화면 폭 단위로 계산한다(세로 차이 × 9/16).
> - 곡선은 웨이포인트를 모두 지나는 Catmull-Rom 곡선이다.
> - 장소 마크 세트는 배경 데이터에 속한다. 같은 배경을 쓰는 연출은 같은 마크를 공유하고, 연출마다 등장 방식(`start` / `time` / `arrive`)만 정한다. 목록에 없는 마크는 숨김이다.
> - 핀의 `resource`는 회사 리소스 테이블의 ID다(R-33). `label`이 비어 있으면 리소스 이름을 쓴다.
> - "지금 열린 맵" 상태(연출 ID와 각 핀의 마지막 위치)를 게임이 들고 있어야 이어가기(R-24)와 맵 유지(R-26)가 된다.
> - 이어가기 연출은 `continue_from`과 함께 시작 상태(`prev_trails`, 각 핀의 첫 점)를 복사해 저장한다. 재생에 앞 연출 데이터가 필요 없다.
> - `group`, `order`는 편집 툴이 이어가기 순서를 관리하려고 쓰는 값이다(별도 툴, C-07). 게임 재생에는 쓰지 않는다.
> - 시간과 한도 값은 코드에 넣지 말고 설정 테이블로 분리해 주세요.

배경 데이터 (장소 마크 세트):

```json
{
  "id": "bg_example",
  "places": [
    { "id": "place_01", "name": "정거장", "pos": [0.10, 0.74] },
    { "id": "place_02", "name": "관측소", "pos": [0.78, 0.30] }
  ]
}
```

## 검증·미결 목록

- 스토리 화면의 실제 UI(대사창 위치, 여백 영역의 처리)에 맞는지 확인 (R-15, R-19)
- 핀 한도(8개)와 웨이포인트 한도(12개)가 실제 스토리 연출에 충분한지 (R-06)
- 기존 스토리 연출의 길이 분포와 비교해 3~8초가 적절한지 (권장 총 길이)
- 핀 규격 리소스 테이블이 있는지, 없으면 어느 테이블을 확장할지 (R-33, 핀 아이콘)
- 스토리 테이블에 `map_play` / `map_close` 명령을 추가할 수 있는지, 명령 이름 규칙 (R-31, R-32)
- 대사 로그에 이동 한 줄을 남기는 방식이 기존 로그 구조에 맞는지 (R-35)
- 맵이 열린 상태를 세이브·불러오기에서 복원해야 하는지
- 배경 담당과 리소스 규격 합의 (R-18)
- 기능을 다 만든 뒤 카메라 연출 여부 재검토 (R-16)

## 개요

스토리 대사 사이에 배경 이미지 한 장을 깔고, 그 위에 장소 이름과 핀(캐릭터나 함대 같은 대상)을 올려 정해진 경로로 이동시킨다. 유저는 글을 읽지 않아도 인물들이 어디서 어디로 움직였는지 알 수 있다.

- **목적**: 이동과 위치 정보를 시각으로 전달해 스토리 몰입을 높인다.
- **감정 중심**: 이동 및 위치 정보. 성공 기준은 "누가 어디서 어디로 갔는지 한 번에 읽힌다"이다.
- **사용 위치**: 스토리 테이블에서 연출 ID로 맵을 열고(재생) 닫는다. 맵은 닫기 명령 전까지 대사 뒤에 남고, 앞 연출이 끝난 상태에서 이어서 시작할 수 있다.
- **기획자 작업**: 편집 툴에서 배경을 고르고, 장소 마크를 새기고, 핀마다 리소스·경로·속도·출발 조건을 정한다. 결과는 아래 「테이블 설계」의 테이블로 저장된다. 툴 상세는 별도 기획서 「맵 이동 연출 편집 툴」(`plans/map-move-tool/`)에 있다.

### 범위

| 포함 | 제외 (다음 버전) |
|---|---|
| 게임 화면의 핀 이동 연출 | 전투·탐험 화면의 맵 |
| 장소 마크(장소 이름 표시) | 3D 지도, 지형 상호작용 |
| 이전 연출에서 이어가기 | 유저가 직접 핀을 조작하는 기능 |
| 스토리 테이블 열기·닫기 명령 | 배경 리소스 제작 (배경 담당) |
| 탭·배속·자동 진행·다시보기·대사 로그 규칙 | 카메라 연출 (기능 완성 후 재검토) |
| 테이블 설계, 설정 키 | 툴 상세 (별도 기획서) |

### 용어

| 용어 | 뜻 |
|---|---|
| 연출 맵 | 이 연출 한 건(장면 하나). 배경 1장, 장소 마크, 핀 여러 개로 이뤄진다 |
| 핀 | Actor 1개(캐릭터, 함대, 오브젝트 등)를 나타내는 표식. 회사 Actor 테이블을 참조한다 |
| 핀 번호 | 핀을 가리키는 번호. 이어가기로 연결된 연출들 사이에서는 같은 번호가 같은 핀이다 |
| 웨이포인트 | 경로를 이루는 점 하나. 좌표 또는 장소 마크를 가리키고, 곡선을 다듬는 핸들을 가질 수 있다 |
| 궤적 | 핀이 이미 지나온 구간. 게임에서는 점선으로 남는다 |
| 장소 마크 | 배경 위 특정 위치에 새긴 장소 이름 |
| 이어가기 | 앞 연출이 끝난 위치에서 다음 연출을 시작하는 것 |
| 맵 열림 | 맵 연출이 재생되었고 아직 닫기 명령을 받지 않은 상태. 대사 뒤에 배경으로 남는다 |
| 이동 시작 | 연출의 시간 기준점(0ms). 등장 페이드인은 이보다 앞에 붙는다 |

## 게임 화면과 툴 화면

같은 데이터라도 게임과 툴에서 보이는 요소가 다르다.

| 요소 | 게임 보기 | 툴 편집 보기 | 상태 |
|---|---|---|---|
| 배경 | 보임 | 보임 | {확정} |
| 장소 마크 | 보임 | 보임, 편집 가능 | {확정} |
| 지나온 궤적 | 점선으로 보임 | 미리보기 재생 시 보임 | {확정} |
| 앞으로 갈 경로 | 안 보임 | 핀 색 파선으로 보임 | {확정} |
| 도착 지점 | 안 보임 | 링으로 보임 | {확정} |
| 웨이포인트와 번호 | 안 보임 | 모든 핀의 점과 번호. 선택하지 않은 핀은 흐리게 | {확정} |
| 앞 연출 궤적 | 설정에 따라 흐린 점선 | 흐린 점선 | {확정} |
| 핀과 이름표 | 보임 | 보임 | {확정} |
| 대사창 영역 | 안 보임 | 켜고 끄는 점선 상자(기본 꺼짐). 맵 유지 중 가려지는 곳 확인용 | {확정} |

## 처리 흐름

1. 스토리 테이블의 `map_play` 명령이 연출 맵을 재생하고, 대사 로그에 「위치 정보 확인」 줄을 남긴다(R-35).
2. 일반 연출이면 배경과 장소 마크를 400ms 동안 페이드인하고(-800ms부터), 핀을 시작 위치에 400ms 동안 페이드인한다(-400ms부터).
3. 이어가기 연출이고 앞 연출의 맵이 열려 있으면 2를 건너뛰고 지금 화면 그대로 0ms에서 시작한다(R-24).
4. 0ms(이동 시작)부터 핀마다 출발 조건이 맞으면 경로를 따라 이동한다. 지난 구간은 점선 궤적으로 남는다.
5. 핀이 도착하면 설정에 따라 그 자리에 남거나 사라진다. 같은 자리에 모인 핀은 나란히 정렬한다(R-17, R-34).
6. 마지막 핀이 도착하고 1000ms가 지나면 연출이 끝나고 다음 대사로 넘어간다. 맵은 `map_close` 명령 전까지 대사 뒤에 남는다(R-26).
7. 재생 중 화면을 탭하면 최종 상태로 300ms 만에 이동한 뒤 끝난다(R-12).

## 이어가기

연속된 이동을 여러 연출로 나눠 대사 사이에 끼워 넣기 위한 기능이다. 예를 들어 "A가 관측소로 간다 → 대사 → A가 탑으로 간다"를 두 연출로 만든다.

- 이어가기 연출은 **앞 연출 ID만** 가진다(R-27). 다음 값은 저장하지 않고 앞 연출 데이터를 따라가며 계산한다.
  - 시작 위치: "앞 연출에서 출발"인 핀은 앞 연출의 같은 핀 번호가 끝난 위치
  - 앞 궤적: 연결된 모든 앞 연출의 경로
  - 장소 마크: 앞 연출 끝에 보이던 마크는 계속 보인다. 이 연출의 장소 목록에는 **새로 보일 마크와 숨길 마크만** 적는다.
- 앞 연출을 고치면 뒤 연출의 시작 위치도 자동으로 따라간다. 툴은 영향받는 뒤 연출 수를 알려준다.
- 다른 연출이 참조 중인 연출은 툴에서 지울 수 없다.
- 앞 연출에 없던 핀을 추가하면 그 핀만 일반 등장(400ms 페이드인)한다.
- 앞 연출에서 "도착 후 사라짐"으로 끝난 핀은 이어서 출발할 수 없다.

## 스토리 테이블 연동

맵은 스토리 테이블의 명령으로 열고 닫는다. 편집 툴은 별도 툴이라 스토리 순서를 모르지만, 게임은 "지금 열린 맵"만 보고 이어가기 여부를 판단하므로 순서 정보가 필요 없다.

| 순서 | 스토리 테이블 | 화면 |
|---|---|---|
| 1 | `map_play 30001` | 맵이 열리고 장면 1 재생 |
| 2 | 대사 | 맵은 대사 뒤 배경으로 남음 |
| 3 | `map_play 30002` | 장면 1의 맵이 열려 있으므로 페이드인 없이 장면 2 재생 |
| 4 | 대사 | 맵은 계속 배경 |
| 5 | `map_close` | 400ms 동안 맵을 닫고 원래 스토리 배경으로 |

## 테이블 설계

> **설계 원칙**
>
> - **한 행 = 한 가지**: 연출, 핀, 웨이포인트, 장소 마크, 연출별 장소 등장을 각각 다른 테이블의 행으로 둔다. 셀 안에 목록(`"1,2|3,4"`)을 넣지 않는다.
> - **사람이 읽는 값**: 좌표는 배경 픽셀 정수, 시간은 ms 정수, 글자는 문자열 키, 선택지는 영문 대문자 열거값.
> - **비워 두면 기본값**: 대부분의 열은 비워 두면 설정 테이블이나 리소스 테이블의 기본값을 쓴다. 기획자가 채우는 칸을 줄인다.
> - **복사본 없음**: 같은 값을 두 곳에 두지 않는다. 장소 좌표는 장소 테이블에만, 이어가기 시작 위치는 앞 연출에만 있다.
> - 테이블 이름과 ID 형식은 회사 규칙을 따르고, 아래 이름과 숫자는 자리표시다. `검증필요`

### MapWaypoint (웨이포인트)

| 열 | 형식 | 예 | 설명 |
|---|---|---|---|
| SceneID | int | 30002 | 연출 |
| PinNo | int | 1 | 핀 |
| Seq | int | 2 | 순서 1부터 |
| PlaceID | int | 1007 | 장소를 가리키면 장소 ID. 이 경우 X, Y는 비운다 |
| X | int | (비움) | 배경 px. PlaceID가 없을 때만 |
| Y | int | (비움) | 배경 px. PlaceID가 없을 때만 |
| InX, InY | int | (비움) | 들어오는 쪽 베지어 핸들. 점 기준 상대 px. 비우면 자동 곡선 |
| OutX, OutY | int | 140, -10 | 나가는 쪽 베지어 핸들. 점 기준 상대 px. 비우면 자동 곡선 |

- 일반 핀은 Seq 1이 시작점이다. `FromPrev` 핀은 시작점이 앞 연출에서 오므로 Seq 1이 첫 목적지다.
- 웨이포인트가 시작점 하나뿐이면(또는 `FromPrev` 핀에 행이 없으면) 이동 없이 위치만 보여준다(R-29).
- 핸들은 점 기준 상대값이라 장소를 옮겨도 곡선 모양이 유지된다. 핸들 한쪽만 적으면 반대쪽은 자동이다. `Curve`가 `LINE`이면 핸들은 무시한다.

### MapScenePlace (연출별 장소 마크 보임/숨김)

| 열 | 형식 | 예 | 설명 |
|---|---|---|---|
| SceneID | int | 30002 | 연출 |
| PlaceID | int | 1007 | 장소 |
| Visible | bool | TRUE | 보임 / 숨김 |

- 일반 연출: `Visible`이 TRUE인 마크만 보인다.
- 이어가기 연출: 앞 연출 끝에 보이던 마크는 적지 않아도 보인다. 새로 보일 마크(TRUE)와 숨길 마크(FALSE)만 적는다.
- 장소는 연출의 배경에 속한 장소여야 한다(같은 BgID).

### MapSpeedPreset (속도 프리셋)

| PresetID | Name | SpeedPx | Memo |
|---|---|---|---|
| 1 | 걷기 | 500 | 인물 기본 |
| 2 | 달리기 | 800 | 급한 이동 |
| 3 | 고속 | 1200 | 함선·비행 |

- `Name`은 툴에만 보이는 이름이라 문자열 키를 쓰지 않는다.

- 속도 단위는 **배경 px/초**이고, 가로 2048px 배경을 기준으로 한다. 배경 가로가 다르면 엔진이 비례로 맞춘다. 값은 모두 `검증필요`.
- 이동 시간 = 경로 길이(px) ÷ 속도 × 1000, 100ms 단위 반올림.

### 왜 이렇게 나눴나

| 판단 | 이유 |
|---|---|
| 웨이포인트를 별도 테이블로 | 점마다 장소 ID와 베지어 핸들을 가질 수 있다. 장소를 옮기면 경로가 따라오고(R-40), 핸들은 필요한 점에만 채운다. 나중에 점별 대기 시간이 필요해지면 열 하나만 추가하면 된다. 변경 이력이 점 단위로 보인다 |
| 장소 마크를 배경에서 분리 | 장소 이름을 문자열 키로 번역하고, 웨이포인트·로그·등장 조건이 같은 장소 ID를 가리킨다 |
| 연출별 장소 보임을 별도 테이블로 | 연출마다 보일 마크를 행으로 적고, 이어가기는 바뀐 것만 적어서 중복이 없다 |
| 핀은 번호(PinNo)로 식별 | 이어가기 연결 안에서 같은 핀을 번호로 이어 붙인다. 같은 Actor 핀이 둘이어도 헷갈리지 않는다 |
| 속도를 프리셋으로 | "걷기가 느리다"는 피드백을 프리셋 값 하나로 모든 연출에 반영한다. 특별한 장면만 DurationMs로 고정한다 |
| 툴용 열(Group, Order, Memo)을 같은 테이블에 | 별도 테이블로 빼면 관리할 곳만 늘어난다. 게임은 이 열을 읽지 않는다 |
| 합치지 않은 것: 핀과 웨이포인트 | 핀 행에 좌표 목록을 넣으면 한 셀에 숫자 수십 개가 들어가 손으로 고치거나 검사하기 어렵다 |
| 열 하나에 뜻 하나 | `StartOffsetMs`는 항상 "기준점에서 몇 ms 뒤"다. 기준점이 무엇인지는 `StartType`이 정한다 |
| bool 표기 | 예시는 TRUE/FALSE로 적었다. 회사 테이블이 1/0을 쓰면 그대로 따른다 |

> **회사 테이블 규칙이 단일 ID 열을 요구하면**
>
> 복합 키를 숫자로 합친다. 예: 핀 행 ID = SceneID × 100 + PinNo, 웨이포인트 행 ID = SceneID × 10000 + PinNo × 100 + Seq. 이 경우 핀 번호와 점 순서는 각각 99까지다(R-06).

## 예외 처리

| 상황 | 처리 | 상태 |
|---|---|---|
| 배경 리소스를 불러오지 못함 | 연출을 건너뛰고 다음 대사로 넘어간다. 오류를 로그에 남긴다. | {확정} |
| Actor가 없거나 핀 리소스 경로가 비어 있음 | 기본 실루엣 핀으로 표시하고 로그를 남긴다. | {확정} |
| 이어가기인데 앞 연출의 맵이 열려 있지 않음 (스토리 스킵, 중간 불러오기, 닫은 뒤 재생) | 앞 연출 데이터로 계산한 시작 상태로 일반 등장(페이드인)한 뒤 이어서 재생한다. | {확정} |
| `FromPrev` 핀인데 앞 연출에 같은 핀 번호가 없거나 사라짐으로 끝남 | 툴이 저장 전에 막는다. 게임에서는 그 핀을 표시하지 않고 로그를 남긴다. | {확정} |
| 출발 조건이 서로를 기다림 (핀 1은 핀 2 도착 후, 핀 2는 핀 1 도착 후) | 툴이 저장 전에 막는다. 게임에서는 0ms에 출발시키고 로그를 남긴다. | {확정} |
| 출발 조건의 기준 핀이 연출에 없음 | 툴이 저장 전에 막는다. 게임에서는 `TIME`으로 보고 로그를 남긴다. | {확정} |
| 웨이포인트·장소 보임이 다른 배경의 장소를 가리킴 | 툴이 저장 전에 막는다. 게임에서는 그 점·마크를 무시하고 로그를 남긴다. | {확정} |
| 맵이 열린 채 이어가기가 아닌 다른 맵 연출 재생 | 지금 맵을 400ms 동안 닫고 새 맵을 일반 등장시킨다. | {확정} |
| 맵이 열린 채 `map_close` 없이 배경 전환·스토리 종료 | 자동으로 닫는다(R-32). 툴·스토리 검사에서 경고한다. | {확정} |
| 재생 중 앱이 백그라운드로 감 | 일시정지하고 복귀하면 이어서 재생한다. | {확정} |
| 탭을 연속 입력 | 첫 탭만 처리한다. 다음 대사 넘김은 연출이 끝난 뒤의 탭부터 받는다. | {확정} |
| 장소 마크와 이름표가 겹침 | 이름표를 위에 그린다(R-28). 겹침 해소는 툴에서 경고만 한다. | {확정} |

## 회사 확인·회의 안건

### 회사에서 확인할 것

사용자가 이 저장소에서 알 수 없는 회사 데이터·구조 정보다. 인계 후 회사에서 확인한다.

- 스토리 화면의 실제 UI(대사창 위치, 여백 영역의 처리)에 맞는지 (R-15, R-19)
- 스토리 배속 배율 값 (R-13)
- Actor 테이블에 함대 등 캐릭터가 아닌 대상도 들어갈 수 있는지, 핀용 원형 아이콘 경로가 있는지 (R-33)
- 스토리 테이블 `map_play` / `map_close` 명령 추가와 명령 이름 규칙 (R-31, R-32)
- 테이블 이름, ID 형식, 단일 ID 열 규칙, bool·열거값 표기, 공용 설정 테이블 유무 (테이블 설계)
- UI 기준 해상도 (R-41, MapConfig)
- 대사 로그 UI에 전용 아이콘 줄과 다시 재생 팝업을 넣는 방식 (R-35, R-45)
- 맵이 열린 상태의 세이브·불러오기 처리: 회사 세이브 구조에 맞춘다
- 로그 아이콘, 이동 효과음 리소스 (아트·사운드)

### 프로그램실 회의 안건

- 편집 툴 플랫폼(엔진 에디터 확장 / 웹 툴) (툴 T-08)
- 툴 편의 기능 범위: 경로 복사, 경로 뒤집기, 이어서 미리보기, PC 단축키 (툴 P-12, P-13, C-05)
- 자유 그리기: 이번 버전은 제외. 프로그램실 의견 확인 (툴 P-02)

### 나중에 다시 볼 것

- 기능을 다 만든 뒤 카메라 연출 여부 재검토 (R-16)
- 속도 프리셋 값(걷기 500, 달리기 800, 고속 1200 px/초)은 시작값. 실제 연출을 만들며 튜닝

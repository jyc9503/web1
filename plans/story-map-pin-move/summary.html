맵 핀 이동 연출

메인 스토리의 중요한 이동 장면에서, 지도 위 핀이 움직여 누가 어디서 어디로 갔는지를 3~8초 안에 보여준다.

확정 65검증필요 19미정 0규칙·기준 ID 기준. 회사 데이터 확인 전 초안

왜 필요한가

글로는 위치가 안 남는다"관측소로 간다"를 대사로만 읽으면 지형과 거리감이 남지 않는다.
여러 명이 흩어지는 장면세 명이 각자 다른 곳으로 가는 장면을 한 화면에서 정리해 준다.
짧게, 가끔메인 스토리의 중요한 이동에만 쓴다. 한 번 3~8초, 탭 한 번이면 끝 상태로 넘어간다.

유저가 보는 장면

이번 범위

넣는 것

  • 지도 위 핀 이동, 지나온 길 점선
  • 장소 이름 표시
  • 앞 연출에서 이어가기, 대사 뒤 지도 유지
  • 탭으로 넘기기, 배속·자동 진행·다시보기·대사 로그
  • 기획자용 편집 툴

빼는 것

  • 카메라 이동·확대 (기능 완성 후 재검토)
  • 유저가 핀을 조작
  • 전투·탐험 화면의 지도
  • 도착 강조 같은 추가 표현

만드는 쪽 규모

담당할 일덩어리
클라이언트지도 레이어, 경로 재생, 이어가기, 스토리 행 연동, 로그중
툴별도 편집 툴(경로 그리기, 장소, 미리보기, 저장·검사)대
데이터엑셀 테이블 5개 + 연출 JSON, 스토리 테이블 열 2개소
아트·사운드지도 배경(스토리마다), 핀 프레임·이름표, 로그 아이콘, 효과음 1종소~중

덩어리는 담당끼리 비교한 크기다. 기간은 회사에서 산정한다.

위험과 대응

  • 폰에서 글자가 작다. 1080 기준 크기를 폰 가로에 줄이면 이름표가 9pt 안팎이 된다. 최솟값을 둬서 받치고, 값은 회사 UI 최소 글자 규칙을 따른다(R-57).
  • 기획자마다 품질이 다르다. 「연출 작성 기준」 9개를 두고, 툴이 길이·동시 이동 수·대사창 가림을 경고한다.
  • 툴이 가장 큰 일이다. 툴 플랫폼(엔진 확장 / 웹)과 편의 기능 범위를 프로그램실과 먼저 정한다.
  • 넓은 폰의 좌우 여백. 지도 전체를 보이게 하므로 19.5:9 폰에서는 좌우에 검은 여백이 생긴다. 다음 버전에서 배경 확장을 검토한다.

이 회의에서 정할 것

1. 이번 버전 범위 승인

제안 위 「넣는 것」 그대로. 카메라는 기능 완성 후.

2. 툴 플랫폼

제안 프로그램실과 엔진 에디터 확장 / 웹 툴 중 결정.

3. 첫 적용 스토리

제안 이동이 많은 메인 스토리 한 장을 골라 기준과 툴을 함께 검증.

자세한 내용: 기획서 본문(10분), 툴 기획서, 툴 사용 안내, 동작 프로토타입. 배경·인물은 자리표시.

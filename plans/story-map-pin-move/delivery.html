§1구현 전달사항

프로그래머에게 전하는 제안이다. 더 나은 방법이 있으면 바꿔도 되고, 화면 결과만 연출 기획서 「부록 C 계산 규칙」과 같으면 된다.

  • 시각 하나로 화면을 계산한다: "연출 데이터 + 연출 시각 t → 배경 불투명도, 장소별 불투명도, 핀별 위치·불투명도·방향, 궤적 길이"를 돌려주는 함수 하나로 만든다. 탭 완료(연출 R-53), 배속(연출 R-54), 툴의 시간 이동, 로그 다시 재생(연출 R-45), 세이브 복원이 모두 t만 바꾸면 해결된다. 겹침 정렬도 t 하나로 계산하므로 프레임 사이 상태가 없다.
  • 미리 계산: 연출을 불러올 때 경로 샘플 점, 구간 길이, 핀별 출발·도착 시각을 한 번 계산해 둔다. 이어가기는 앞 연출을 따라가 시작 상태를 계산한다(연출 F-10).
  • 궤적은 코드로 그린다: 리소스 없이 핀 색의 둥근 점선을 그린다.
  • 미리 불러오기: 스토리에 들어갈 때 그 스토리 행들이 가리키는 연출의 배경과 핀 아이콘을 미리 불러온다. 재생 순간에 멈칫하지 않게 한다. 검증필요
  • 데이터 검사: 연출 JSON 안의 actor_id, place_id는 엑셀 검사가 닿지 않는다. 툴의 저장 전 검사(편집 툴 기획서 T-07)와 같은 규칙으로 빌드 때 한 번 더 검사하는 스크립트를 둔다. 손으로 고친 JSON도 걸러진다.
  • JSON 형식 버전: version이 아는 값이 아니면 연출을 건너뛰고 로그를 남긴다. 형식을 바꿀 때 버전을 올린다.
  • 세이브: 스토리 중간 저장이 있다면 "지금 열린 연출 id" 하나만 저장한다. 복원할 때 그 연출의 최종 상태를 계산해 바로 유지 상태로 띄운다.
  • 확인용 기능: 연출 id를 넣으면 스토리 없이 바로 재생하는 개발용 명령이 있으면 기획·QA 확인이 빨라진다.
  • 로그: 연출 기획서 「부록 E 예외 처리」의 모든 줄은 연출 id와 핀 번호를 담은 로그를 남긴다.

# 결정 기록: 스토리 맵 핀 이동 연출

## 게임 맥락
- 회사 정보: Actor 테이블(이름·리소스 경로), 배속은 켬/끔, 시간 ms, 문자열 키. 상세는 `docs/game-context.md`의 「사용자가 알려준 사실」.
- 대상: 카오스 제로 나이트메어(카제나). 상세는 `docs/game-context.md` (웹 검색 요약 기반, 전부 검증필요).
- 이 기획은 **스토리 진행 중에 나오는 연출**이다.
- 스토리 화면의 UI 구성(대사창 위치, 스킵 버튼, 화면 방향)은 아직 모른다. 기존 스토리 UI를 재사용한다고 가정한다 `검증필요`.

## 인터뷰 결과 (2026-11-08)
| 항목 | 사용자 답변 | 해석 |
|---|---|---|
| 기획 종류 | 연출 기능 | 스토리 연출 기능 1개 |
| 연출 내용 | 배경 리소스 한 장 위에 캐릭터 핀을 놓고, 핀이 지정한 경로로 이동 | 맵 핀 이동 연출 |
| 배경 | 배경 리소스는 배경에서 지원 | 배경 담당(팀)이 리소스를 제공한다고 해석 `검증필요` |
| 툴 | 기획자가 툴에서 각 핀의 캐릭터와 경로를 지정 | 편집 툴이 필요하다 |
| 감정 중심 | 이동 및 위치 정보 | 몰입의 핵심은 "누가 어디서 어디로 가는지"가 한눈에 읽히는 것 |
| 결과물 | 기획서 HTML, 화면 시안, 동작 프로토타입, 한 장 요약 | |
| 스킵·다시보기 | 알아서 제안 | R-12, R-14로 제안 |
| 규모 | 알아서 제안 | 장면 단위 3~8초로 제안 |

## 확정
- 배경 리소스 1장 위에 캐릭터 핀을 올린다. (R-01)
- 핀 1개는 캐릭터 1명이다. (R-02)
- 핀은 기획자가 지정한 경로를 따라 이동한다. (R-03)
- 기획자가 툴에서 핀의 캐릭터와 경로를 지정한다. (R-04, T-01, T-02)

- 게임에서는 이동한 경로를 점선으로 남긴다. (R-09)

- 툴의 경로 그리기 방법은 별도 기획서 `plans/map-move-tool/`로 분리한다.

## 확정 (2026-11-08, v0.5 결정)
- 회사는 시간에 ms, 글자에 문자열 테이블 키를 쓴다. (R-37, R-39)
- 좌표는 배경 원본 px 정수. 위치·길이·속도는 배경 기준, 표시 크기는 UI 기준 해상도 px. (R-05, R-41)
- 0ms = 이동 시작. 페이드인은 그 앞 음수 구간. (R-37)
- 이동 시간은 속도 프리셋으로 계산, 필요 시 고정. 출발 조건(시간/출발 후/도착 후). (R-08, R-38)
- 이어가기는 앞 연출 ID만 저장하고 나머지는 계산. (R-27)
- 데이터는 테이블 8개로 설계(한 행 = 한 가지). 설정 키 목록으로 튜닝 값을 모은다.

## 확정 (2026-11-09, 핵심 규칙 확인)
- 검증필요였던 핵심 규칙 16건을 사용자가 확인해 확정.
- 핀은 Actor 테이블 참조(ActorID). 배속은 켬/끔.
- 핀·점 한도 없음.
- 곡선은 자동 곡선 + 필요한 점만 베지어 핸들.
- 장소 마크는 연출마다 보임/숨김만(등장 타이밍 제거).
- 대사 로그는 맵 연출마다 공통 한 줄(전용 아이콘 + "위치 정보 확인"), 누르면 연출 다시 재생.

## 확정 (2026-11-11, 미결 정리)
- 배경은 비율만 16:9 통일, 해상도 자유. 속도는 2048 폭 기준 환산. (R-18)
- 로그 다시 재생은 로그 위 팝업이 기본, 회사 로그 UI에 따라 조정. (R-45)
- 세이브 시 맵 상태 처리는 회사 세이브 구조에 맞춘다(회사 확인).
- 예외 처리, 아트 표현(핀 링·삼각형, 알약 이름표, 핀 색 점선 궤적, 점+외곽선 장소 글자) 확정.
- 속도 프리셋 500/800/1200은 시작값으로 두고 튜닝.
- 툴: 모든 핀의 점 표시, 재생해도 보기 유지, 대사창 가이드는 옵션, 타임라인 막대는 보기 전용. 자유 그리기는 제외하고 회의에서 확인. 편의 기능 범위와 툴 플랫폼은 회사·프로그램실과 결정.

## 확정 (2026-11-15, 회사 테이블 규칙)
- 회사 스토리 테이블은 한 행에 `id`가 있고 옆으로 열이 늘어선 형태. 내보내면 한 행이 `{}`.
- 테이블은 행마다 `id`, 참조는 `link_*_id`, 열 이름은 소문자 + 밑줄, 그룹은 쓰지 않는다. 테이블 원본은 엑셀, 연출 데이터는 JSON인 경우도 있다.
- 저장 형태는 엑셀 + JSON 나눠 쓰기: 핀·경로 점·장소 보임은 연출 1건당 JSON 1개, 배경·장소·연출 머리·속도 프리셋·설정은 엑셀. 스토리 행은 연출 id만 가리킨다.
- 프로토타입은 한 파일, 탭 3개(스토리 시연 / 편집 툴 / 데이터).

## 검토 반영 (2026-11-21, 사용자 인터뷰)
- 검토 관점은 플레이어 경험 → 기획자 작업 효율 → 문서 읽기 쉬움 순. 범위는 지금 안에서 다듬기(새 기능 없음).
- 사용 장면은 메인 스토리에서 가끔. 툴은 스토리 기획자 여러 명이 쓴다.
- 기획서는 본문과 부록으로 나눈다. 회의용 한 장은 기획팀 리드·PD 대상.
- 판단이 갈리면 추천안으로 반영하고 `검증필요`, 끝에 몰아서 확인.

## 확정 (2026-11-21, 검토 결정)
- 앞 연출 궤적은 바로 앞 연출 하나만 흐리게 남긴다. (R-56, `MAP_PREV_TRAIL_DEPTH` 1)
- 폰에서 핀·이름표·장소 글자에 최솟값을 둔다. 값은 회사 UI 최소 글자 규칙을 따른다. (R-57)
- 연출 작성 기준 수치: 동시 이동 핀 3개 이하, 도착지·장소는 화면 아래 22% 밖, 보이는 장소 8개 이하. (G-02, G-04, G-05)

## 확정 (2026-11-21, 복잡도 줄이기)
- 이어가기 연출에서 앞 연출과 같은 번호의 핀은 표시 없이 자동으로 앞 끝 위치에서 출발한다. `from_prev` 필드는 없앤다. (R-23)
- 핀 출발 조건은 시간 / 다른 핀 도착 후 두 가지만. 함께 출발은 같은 시간으로. (R-38, F-06)
- 문서: 본문에는 설정 키 이름 없이 값만 쓴다. 자리표시 이유뿐인 표에는 배지를 붙이지 않는다. 규칙은 그룹 안에서 번호 순으로 두고, 본문의 ID 참조는 꼭 필요한 곳만 남긴다.
- 하지 않기로 한 것: 핀 고급 옵션 접기, 겹침 다시 정렬 빼기, 흐름 설명 하나로 줄이기·버전 통일.

## 확정 (2026-11-21, 2차 복잡성 검토)
- 도착 후 사라짐(`on_end`, R-47)을 없앤다. 도착한 핀은 남고, 빼려면 다음 이어가기 연출의 핀 목록에서 뺀다(R-11, R-49).
- 핀별 궤적 끄기(`trail`), 이징 선택(`easing`), 핀 색 직접 지정(`color`)을 없앤다. R-50 삭제.
- 겹친 핀의 다시 정렬 애니메이션을 없앤다. 묶음이 바뀌면 바로 새 자리에 놓는다(R-34).
- 설정 키를 35개에서 23개로: 400ms 페이드는 `MAP_FADE_MS` 하나, 계산 상수는 부록 C 계산식 안으로.
- 문서: 본문은 무엇을 만드는지만 둔다. 구현 규칙·상태 전이표·스토리 테이블·이어가기 세부는 부록 J, 용어·읽는 법은 부록 K. 규칙은 읽는 순서로 배치. 확정 배지는 그리지 않는다. 문서 묶음 버전은 하나(v0.18).
- 남은 결정 후보: 배경 해상도 고정(2048×1152) 여부.

## 확정 (2026-11-21, 3차 정리)
- 맵 배경은 2048×1152로 고정한다. 더 큰 원본은 같은 비율로 줄여 넣는다. (R-18) 속도 환산과 해상도 교체 시 좌표 변환은 없앤다.
- 과한 작성 기준을 줄인다: 직전 대사 요구(G-03), 이어가기로 나누는 기준(G-07), 이름표 6자·중복 금지(G-08), 색 때문에 핀 번호 바꾸기(G-09) 삭제. G-01은 "8초 이하"만.
- 아트·사운드 전달사항은 부록 L, 프로그램실 회의 안건은 부록 F 끝으로 옮긴다.

## 확정 (2026-11-21, 경고 정리, v0.20)

- 툴 안내는 해당할 때만 띄운다. 매번 같은 말을 띄우지 않는다(툴 E-06의 원칙을 경고·안내 전체로 넓힘).

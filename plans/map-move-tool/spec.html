§1개요

「스토리 맵 핀 이동 연출」(plans/story-map-pin-move/)의 데이터를 만드는 편집 툴이다. 연출 규칙(R-xx)은 그 기획서를 따르고, 이 문서는 툴에서 어떻게 만드는지만 다룬다.

  • 사용자: 스토리 연출을 만드는 기획자
  • 목표: 연출 하나를 5분 안에 만든다. 점 몇 개를 찍으면 곡선이 나오고, 앞 연출에서 이어갈 때는 버튼 하나로 시작 상태가 채워진다. 검증필요
  • 원칙: 툴에서 보는 미리보기와 게임 화면이 같아야 한다. 결과는 연출 기획서 「테이블 설계」의 테이블로 저장한다.
  • 단위: 툴 화면의 좌표·길이는 배경 px, 시간은 ms, 속도는 px/초로 표시한다(연출 R-05, R-37, R-41).
  • 동작 프로토타입(plans/story-map-pin-move/proto/)이 이 문서의 주요 기능을 구현해 두었다.

ID 요구 상태

K-04 출발 조건: 시간 / 다른 핀 출발 후 / 다른 핀 도착 후 + 지연(ms). 기준 핀은 같은 연출의 핀 목록에서 고른다. 확정
K-05 타임라인 막대: 재생 바 위에 핀별 이동 구간을 막대로 보여준다. 출발 조건으로 묶인 핀은 화살표로 잇는다. 막대를 끌면 지연(ms)이 바뀐다. 검증필요

§5경로 그리기

경로는 점(웨이포인트)을 찍어서 만든다. 직선·곡선은 그리는 방법이 아니라 경로의 속성이다. 같은 점으로 직선과 곡선을 오가며 비교할 수 있다.

그리기 방식

ID 방식 동작 상태
P-01 점 찍기 (기본) 캔버스를 탭할 때마다 경로 끝에 점을 추가한다. 검증필요
P-02 자유 그리기 손가락이나 마우스로 선을 그리면 놓는 순간 점 몇 개로 자동 변환한다(P-08). 이후에는 점 찍기와 같은 방식으로 다듬는다. 검증필요

경로 형태

ID 형태 설명 상태
P-03 곡선 (기본) 모든 점을 지나는 부드러운 곡선(Catmull-Rom). 핸들 조작 없이 점만으로 모양이 정해진다. 검증필요
P-04 직선 점과 점을 직선으로 잇는다. 길·복도처럼 꺾이는 이동에 쓴다. 검증필요
P-05 구간별 형태 한 경로 안에서 구간마다 직선/곡선을 다르게 지정할지. 미정

곡선 방식 선택 이유

베지어 곡선은 점마다 핸들 두 개를 조절해야 해서 폰과 마우스 모두 손이 많이 간다. Catmull-Rom은 점만 찍으면 그 점을 모두 지나는 곡선이 나와서 "여기를 지나간다"는 기획 의도가 그대로 데이터가 된다. 대신 곡선이 점 사이에서 살짝 부풀 수 있어, 모양을 더 잡고 싶으면 점을 하나 더 넣는다(P-06).

점 편집

ID 동작 방법 상태
P-06 점 삽입 경로 선 위를 탭하면 그 위치에 점을 끼워 넣는다. 검증필요
P-07 점 이동 / 삭제 점을 끌어서 옮긴다. 점을 선택하고 삭제 키(폰은 길게 누르기)로 지운다. 검증필요
P-08 자유 그리기 단순화 그린 선을 Douglas-Peucker 방식으로 줄인다. 허용 오차는 화면 폭의 0.8%부터 키우며 점이 12개 이하가 될 때까지 반복한다. 검증필요
P-09 장소 마크 스냅 점을 장소 마크 근처(배경 폭 2% 이내)에 놓으면 마크에 붙는다. 붙은 점은 좌표 대신 장소 ID로 저장되어, 장소를 옮기면 경로도 따라간다(연출 R-40). 붙은 점은 다이아몬드 모양으로 표시한다. 켜고 끌 수 있다(기본 켬). 검증필요
P-10 시작점 고정 FromPrev 핀의 시작점은 앞 연출에서 온다. 저장하지 않고 자물쇠로 표시하며 옮기거나 지울 수 없다. 검증필요
P-11 실행 취소 / 다시 실행 최소 50단계. 점 추가, 이동, 삭제, 속성 변경, 이어가기 가져오기를 모두 포함한다. 검증필요
P-12 경로 복사 선택한 핀의 경로를 다른 핀에 붙여 넣는다. 함께 이동하는 무리를 만들 때 쓴다. 붙여 넣은 경로는 조금 옆으로 비켜 놓는다. 검증필요
P-13 경로 뒤집기 경로의 시작과 끝을 바꾼다. 왕복 이동을 만들 때 쓴다. 검증필요

속도

이동 시간은 기본적으로 속도 프리셋과 경로 길이로 자동 계산된다(연출 R-08). 경로를 고쳐도 속도는 그대로다. 특별한 장면만 시간을 직접 고정한다.

ID 요구 상태
P-14 속성 패널에 경로 길이(px), 속도(px/초), 계산된 이동 시간(ms)을 표시한다. 검증필요
P-15 속도 프리셋: 핀마다 프리셋(걷기, 달리기, 고속)을 고른다. 기본은 걷기. 「시간 고정」을 켜면 이동 시간(ms)을 직접 입력하고 프리셋은 무시한다. 저장 열: SpeedPreset, DurationMs. 확정

§6장소 마크 편집

ID 요구 상태
M-01 장소 마크 탭에서 캔버스를 탭하면 마크를 추가하고 이름 입력란에 커서를 둔다. 이름은 문자열 키로 저장하고, 툴에는 번역 전 원문을 보여준다. 검증필요
M-02 마크를 끌어 옮기고, 이름을 바꾸고, 지운다. 검증필요
M-03 장소 마크 세트는 기획자가 이 툴에서 관리하고 MapPlace 테이블에 배경별로 저장한다. 같은 배경을 쓰는 모든 연출이 같은 세트를 쓴다. 한 연출에서 마크를 옮기면 그 장소를 지나는 모든 경로와 다른 연출에도 반영된다는 안내를 띄운다. 확정
M-04 연출마다 마크의 등장 방식을 고른다: 처음부터 / 시간 지정(ms, 이동 시작 기준) / 핀 도착 시 / 숨김. MapScenePlace 테이블에 저장한다. 이어가기 연출에서는 앞 연출 끝에 보이던 마크가 자동으로 보이고, 바뀐 것만 저장한다. 확정
M-05 마크 이름은 최대 10자. 이름이 겹치거나 비면 저장 전에 알린다. 검증필요

§7이어가기

ID 요구 상태
C-01 「앞 연출에서 이어가기」 버튼. 같은 묶음(C-07)에서 바로 앞 순번의 연출을 기본으로 추천하고, 목록에서 다른 연출도 고를 수 있다. 확정
C-02 가져오는 것: 배경, 앞 연출 ID, 그리고 앞 연출 핀마다 같은 번호·리소스·이름표·속도 설정의 FromPrev 핀. 시작 위치, 앞 궤적, 장소 마크 표시는 저장하지 않고 앞 연출에서 계산해 보여준다. 검증필요
C-03 저장하는 이어가기 정보는 PrevSceneID 하나다(연출 R-27). 확정
C-04 앞 연출을 고치면 뒤 연출의 시작 위치·앞 궤적이 자동으로 바뀐다. 저장할 때 "뒤 연출 N개의 시작 위치가 바뀝니다"를 알리고, 뒤 연출에서 깨지는 핀(앞 연출에서 사라진 핀 번호)을 오류 목록에 띄운다. 검증필요
C-05 연출 목록에서 이어가기 연결(1 → 2 → 3)을 보여주고, 사이에 대사가 있는 것처럼 연결된 연출을 차례로 미리보기 재생할 수 있다(맵 유지 포함). 검증필요
C-06 앞 연출에서 사라짐(on_end: 사라짐)으로 끝난 핀은 가져오지 않는다. 검증필요
C-07 별도 툴이라 스토리 순서를 모른다. 그래서 MapScene의 Group(예: C03_MOVE)과 Order로 툴 안에서 목록 순서를 관리한다. 스토리 테이블은 map_play <SceneID>로만 참조하고, 게임은 순서 정보 없이 "열린 맵"으로 이어가기를 판단한다. 검증필요
C-08 다른 연출이 PrevSceneID로 참조 중인 연출은 지울 수 없다. 지우려면 뒤 연출의 연결을 먼저 끊는다. 검증필요

§8저장과 검증

ID 요구 상태
T-05 툴 안에서 미리보기 재생(재생·일시정지·처음으로·배속·시간 이동). 결과는 게임과 같아야 한다. 검증필요
T-06 연출 기획서 「테이블 설계」 형식(MapScene, MapPin, MapWaypoint, MapScenePlace, MapPlace)으로 저장하고 불러온다. 「테이블로 보기」는 현재 연출의 행을 탭 구분 텍스트로 보여주어 엑셀에 그대로 붙여 넣을 수 있다. 검증필요
T-07 저장 전에 검사한다: 핀·점 한도 초과, 배경 범위 밖 좌표, 경로가 빈 핀, 이름 키가 없는 장소 마크, 도착할 핀이 지워진 장소 마크, 앞 연출에 없는 FromPrev 핀, 서로를 기다리는 출발 조건, 끊긴 이어가기 연결, 속도 경고(P-16), 대사창 영역 안의 도착 지점(V-05). 검증필요
T-08 기존 스토리 툴과 분리된 별도 툴로 만든다. 스토리 노드는 연출 맵 ID로 참조한다. 확정
